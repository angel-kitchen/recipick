# Recipick 프론트엔드

React + Vite로 만든 웹 화면입니다. 백엔드(Spring Boot) API를 호출합니다.

## 준비물
- Node.js 20.19 이상 또는 22.12 이상(이 프로젝트는 24에서 확인), npm

## 실행
1. 백엔드를 먼저 로컬(8080 포트)에 띄웁니다.
2. 터미널에서 아래를 실행합니다.

```bash
cd frontend
npm install     # 처음 한 번만
npm run dev     # http://localhost:5173
```

개발 서버가 `/api` 요청을 `http://localhost:8080`으로 대신 전달합니다(`vite.config.js`). 브라우저에는 같은 주소로 보이기 때문에 CORS 설정이 필요 없고 로그인 쿠키도 그대로 동작합니다. 백엔드 주소가 다르면 `VITE_API_TARGET=http://주소:포트 npm run dev`로 바꿉니다.

## 빌드
```bash
npm run build   # dist/ 폴더에 정적 파일이 생깁니다
```
`dist/`는 nginx 같은 웹 서버가 그대로 내려줄 수 있는 HTML·CSS·JS 묶음입니다. 서버 배포는 별도 이슈로 다룹니다.

## 홈 영상 넣는 법
`frontend/public/videos/hero.mp4`가 홈 첫 화면에 소리 없이 반복 재생됩니다. 출처와 라이선스는 `public/videos/CREDITS.md`에 있습니다.
- 바꾸려면 같은 이름으로 덮어씁니다. 10~15초, 1080p 이하, 5MB 이하, mp4(H.264) 권장
- 저작권이 없는 영상(예: Pexels, Pixabay)만 사용합니다.
- 파일이 없으면 짙은 녹색 바탕과 문구만 보입니다.

## 화면
| 경로 | 화면 | 로그인 |
| --- | --- | --- |

| `/auto-carts/:id` | 자동 장바구니 미리보기·확정(멤버십 전용) | 필요 |
| `/addresses` | 배송지 등록·수정·선택·삭제, 서비스 지역 확인 | 필요 |
| `/products` | 상품 목록(장바구니 담기) | 필요 |

결제(PortOne), 마이페이지, 북마크, 주문 목록은 아직 없습니다.

### 관리자 화면 (`/admin`)
서비스 화면과 로그인이 따로입니다. 관리자 토큰도 회원처럼 메모리에만 두고, 새로고침하면 리프레시 쿠키로 다시 받습니다. 쿠키 이름이 회원과 같아서 한 브라우저에서 둘을 같이 로그인하면 나중 로그인이 앞을 덮어씁니다. 함께 테스트할 때는 시크릿 창을 쓰세요.

| 메뉴 | 기능 | 권한 |
| --- | --- | --- |
| 주문 | 목록·상세, 수락, 거절(결제 취소) | 운영자, 마트 관리자 |
| 상품·재고 | 등록·수정·삭제, 가격, 판매 상태, 재고 조정·이력 | 운영자, 마트 관리자 |
| 마트 | 좌표·반경·운영 상태 수정 | 운영자, 마트 관리자 |
| 레시피 | 등록·수정, 재료 연결, 자동 담기 켜기·끄기, 공개 상태 | 운영자 |
| 재료, 카테고리 | 등록·수정(카테고리는 삭제도) | 운영자 |
| 회원·멤버십 | 회원 검색, 멤버십 지급 | 운영자 |
| 결제, 감사 로그 | 조회 | 운영자 |

로컬 시드 계정은 `super01`(운영자), `samcheong01`, `haan01`(마트 관리자)이고 비밀번호는 `AdminSeedSqlIntegrationTest`의 `TEST_PASSWORD`와 같습니다. 운영 배포에서는 이 시드를 읽지 않습니다.

## 화면을 끝까지 써 보려면
1. 회원가입 → 로그인 → `/addresses`에서 "주소 찾기"로 배송지를 등록하면 이용 마트가 정해집니다(법정동 코드는 검색 결과에서 자동으로 들어갑니다). 시연 지역은 삼청동·하안동이며 칩을 누르면 바로 채워집니다. 주소 검색은 카카오(다음) 우편번호 스크립트를 쓰므로 인터넷이 필요합니다.
2. 이용 마트가 정해지면 상품 담기 → 장바구니 → 주문이 동작합니다.
3. 자동 장바구니(레시피 상세·AI 입력)는 **멤버십 회원 전용**입니다. 관리자 화면 "회원·멤버십"에서 지급합니다. 자동 담기가 켜진 레시피와 재료에 연결된 상품은 `data-product-local.sql` 시드가 넣습니다.
4. 인증 API는 IP당 1분에 10회로 제한됩니다. 테스트하다 "요청이 너무 많습니다"가 나오면 1분 기다립니다.

## 폴더 구조
```
src/
  api/client.js        API 호출 공통 처리(응답 껍데기 벗기기, 토큰 첨부, 401 재발급)
  auth/AuthContext.jsx 로그인 상태
  components/          헤더, 푸터, 지도, 공통 부품
  pages/               화면 하나당 파일 하나
  styles/              tokens.css(색·간격), layout.css, home.css(테슬라 스타일), shop.css(스타벅스 스타일)
  labels.js            서버 enum 값을 화면 글자로 바꾸는 표
```

## 디자인 규칙
- 홈: Tesla 디자인 문서의 규칙(풀스크린, 여백, 4px 버튼, 그림자 없음)
- 쇼핑 화면: Starbucks 디자인 문서의 규칙(크림 바탕, 알약 버튼, 12px 카드)
- 색은 초록 계열로 통일합니다. 글꼴은 Pretendard입니다.
- 두 브랜드의 로고·사진·영상은 사용하지 않습니다.

## 인증 방식
액세스 토큰은 브라우저 메모리에만 보관합니다. 새로고침하면 httpOnly 리프레시 쿠키로 `POST /api/auth/reissue`를 호출해 다시 받습니다.

## 지도 데이터
홈 지도는 로그인 없이 `GET /api/config/marts`를 호출해 운영 중인 마트를 표시합니다. 호출이 실패하거나 목록이 비어 있으면 지도 아래에 안내 문구만 보여주고, 임시 데이터는 쓰지 않습니다.

## 현재 위치 기능(카카오 지도 키)
배송지에서 '현재 위치로 찾기'는 카카오 지도 JavaScript SDK로 좌표를 주소와 법정동 코드로 바꿉니다.
- 키는 `frontend/.env.local`에 `VITE_KAKAO_JS_KEY=발급한키` 한 줄로 넣습니다(`.env.example` 참고). 이 파일은 저장소에 올라가지 않습니다.
- 키는 카카오디벨로퍼스에서 앱을 만들고 `카카오맵 > 사용 설정`을 켠 뒤, 플랫폼 키의 JavaScript 키를 씁니다. 같은 화면의 JavaScript SDK 도메인에 `http://localhost:5173`과 운영 주소를 등록해야 합니다.
- Vite는 시작할 때만 환경 변수를 읽으므로 키를 바꾸면 개발 서버를 다시 띄웁니다.
- 키가 없으면 '현재 위치로 찾기' 버튼만 비활성이 되고, 주소 직접 검색은 그대로 동작합니다.
- 운영 빌드에는 CI의 `frontend-build`에 같은 이름의 변수가 있어야 버튼이 켜집니다.
- 현재 위치 좌표는 주소를 찾기 위해 카카오 지도 SDK(Geocoder)로 전달됩니다. Recipick 서버로는 보내지 않고 저장하지 않으며, 사용자가 확정한 배송지만 서버에 저장합니다.
