# 결제 PG 실연동 검증 결과 (토스페이먼츠 V2 테스트 채널)

시연용 결제를 실제 출금 없이 운영하기 위해, 기존 결제 코드를 유지하면서 PortOne 채널만 토스페이먼츠 V2 TEST 채널로 변경하여 실제 PG 응답으로 결제 흐름을 검증했다.

별도의 시연용 가짜 PG를 구현하지 않고, 기존 결제·취소·환불·멤버십 구조를 활용할 수 있다는 근거를 기록한다.

## 3. 시나리오별 상세

### 3-1. 카드 등록 — `customerKey` 규칙 위반 발견

**최초 증상**

토스 카드 등록창 호출 시 `INVALID_CUSTOMER_KEY` 오류가 발생했다. 발급 요청 응답의 `customerId`가 회원 ID 원값인 `"6"`이었다.

**원인**

토스페이먼츠 `customerKey`는 2~255자 길이와 허용 문자 규칙을 갖는다. 한 자리 회원 ID는 최소 길이 조건에 맞지 않는다.

**수정**

`PortOneCustomerId.of(memberId)`를 도입해 고객 식별자를 `member-{회원ID}` 형식으로 통일했다. 카드 등록 발급 요청, 빌링키 소유 검증, 자동청구 요청에서 같은 고객 식별자를 사용하도록 변경했다.

**결과**

토스 카드 등록창 정상 호출, 서버의 TEST 채널 및 고객 식별자 검증 통과, 카드 등록 API 성공.

관련 변경: PR #550, 이슈 #549.

### 3-2. 첫 구독 결제 (E-3 일부 확인)

확인한 내용:

- `mpay_` + UUID 형태의 결제 ID가 토스에서 수용됨
- 빌링키를 이용한 3,900원 청구 성공
- 고객 이름·이메일·전화번호, `productCount`를 포함한 요청이 거절되지 않음
- 같은 결제 ID의 GET 재조회로 결제 성공 확인
- 구독 응답 `PAID`
- 멤버십 활성화 및 자동 갱신 설정 반영

이용 기간: PG 결제 시각을 시작점으로 하는 달력 기준 1개월. 종료는 다음 달 결제 기준일의 같은 시각이다. 고정 30일이 아니다.

미확인 사항: PG `paidAt`의 원문 타임존 표기. 또한 KG이니시스 전용 필드 호환성은 이번 토스 검증 결과로 증명하지 않는다.

따라서 토스 첫 청구 흐름은 PASS, 전체 E-3 계약 검증은 일부 미완료로 기록한다.

### 3-3. 즉시 해지 → 일할 환불

| 항목 | 관측값 |
| --- | --- |
| 최초 결제 금액 | 3,900원 |
| 사용 일수 | 1일 |
| 사용 이용료 | 130원 |
| 위약금 | 780원 |
| 환불 금액 | 2,990원 |
| 환불 상태 | `COMPLETED` |
| 운영 확인 필요 | `false` |

환불 계산: 3,900 − 130 − 780 = 2,990원

토스 PG에서 금액 지정 부분 취소가 처리됐고, 로컬에서는 웹훅 없이 취소 결과 확정 경로로 완료됐다.

미확인 사항: 부분 취소 후 PG GET 응답의 `PARTIAL_CANCELED` 원문 상태.

### 3-4. 상품 일반결제 → 전액 취소

결제 수단: 카카오페이. 내부 결제 수단은 카드로 기록됐다.

관측 결과:

- 상품 결제 금액: 12,900원
- 결제 성공 및 회원 취소
- `paymentStatus: CANCELED`
- `refundStatus: COMPLETED`
- `refundAmount: 12900`
- 주문 상태: `REFUNDED`

PR #546에서 보강한 회원 환불 흐름이 토스 PG에서도 정상적으로 동작한 것을 확인했다.

### 3-5. 결제 대기 5분 만료 및 늦은 승인

결제창에서 카드사 인증을 진행하는 동안 주문의 결제 대기 시간이 만료됐다.

| 관측 시각(KST) | 사건 |
| --- | --- |
| 16:32:33 | `PAYMENT_EXPIRE` 실행. 주문 `CANCELED`(`PAYMENT_TIMEOUT`), 결제 `FAILED`(`EXPIRED`) |
| 16:33:47 부근 | 서버 SYSTEM 환불 요청 시각 기록 |
| 16:33:49 | PG 조회 결과에 기록된 승인 시각(`paidAt`) |
| 16:33:51 | PG 취소 성공 및 SYSTEM 환불 완료 |

서버 확정 처리에서 이미 종료된 결제에 대한 승인을 확인하였고, `ALREADY_CLOSED` 판정에 따라 주문·결제 상태를 되돌리지 않고 SYSTEM 전액 환불을 실행했다.

최종 상태:

- 주문: `CANCELED`
- 결제: `FAILED`(`EXPIRED`)
- 환불: `COMPLETED`, 12,900원
- PG 상태: `CANCELLED`
- PG 취소 금액: 12,900원
- PG 채널: `TEST`, `TOSSPAYMENTS`

최종 DB와 PG 조회 결과가 일치했다.

주문 화면이 잠시 `REQUESTED` 및 환불 0원으로 보였으나, 최종 DB 조회 시 환불은 완료 상태였다.

PG 승인 시각과 서버 환불 요청 시각의 순서는 서로 다른 시스템에서 기록된 시간이다. 약 2초의 차이가 있었지만 원인은 확인하지 못했다. PC 시계 차이 등은 가능성일 뿐 확정하지 않는다.

## 4. 미검증 항목

| 항목 | 미검증 사유 및 영향 |
| --- | --- |
| E-3 일부 | `paidAt` 원문 타임존, KG이니시스 전용 요청 필드 |
| E-4 | 카드 거절 시 같은 결제 ID의 GET 결과가 `FAILED`인지 404인지 미확인 |
| E-6 | 동일 결제 ID로 청구 POST를 재실행할 때의 실제 PG 응답 미확인 |
| 같은 멱등 키로 회원 취소 재요청 | 실제 PG 재호출 검증 미실시. `MEMBER_REFUND_AUTO_REPOST_ENABLED=false` 유지 |
| 웹훅 | 로컬에 외부 웹훅이 도달하지 않아 운영 환경에서 별도 검증 필요 |
| PC 카드사 직접 인증 | 카드사 앱·보안 프로그램 인증 제약으로 정상 완료 여부 미확인 |
| 부분 취소 후 GET 원문 | `PARTIAL_CANCELED` 응답 세부 구조 미기록 |

결제 결과가 불명확할 때 서버는 새 결제 ID를 임의로 발급하지 않고 동일 ID를 재조회하도록 설계되어 있다. 해당 장애 분기 전체를 실제 PG에서 재현했다는 의미는 아니다.

## 5. 운영 반영 시 유의점

- 기존 KG이니시스 발급 빌링키는 채널에 종속될 수 있으므로, 토스 전환 후 회원 카드 재등록 여부를 확인한다.
- 운영 Compose에 카드 등록·멤버십 청구 스위치를 전달하는 변경은 PR #552에서 완료했다.
- 기존 빌링키, 미해결 결제 시도, 갱신 대상 확인 후 카드 등록과 자동결제를 단계적으로 활성화한다. 상세 절차는 PR #552 본문을 따른다.
- LIVE 빌링키 신규 등록은 `BillingKeyIssuanceVerifier`에서 차단한다.
- 빌링키 암호화 작업은 PR #562로 별도 진행하며, 운영 암호화 키·Expand DDL 적용 전에 머지하지 않는다.
- 신규 LIVE 등록 차단만으로 과거 발급된 모든 빌링키의 청구 위험이 자동으로 제거되는 것은 아니다.

## 결론

토스페이먼츠 V2 TEST 환경에서 일반결제·전액 취소, 빌링키 등록, 첫 구독 청구, 즉시 해지 부분 환불, 결제 만료 후 SYSTEM 환불을 실제 PG 응답으로 확인했다. 따라서 별도 시연용 PG를 구현하지 않고 기존 결제 구조를 재사용하는 방향에 근거가 있다. 다만 미검증 장애 시나리오와 운영 활성화 전 점검 항목은 별도로 관리한다.
