> 현재 설정과 그 근거. 모델은 `evaluation.md` 5절의 비교 결과로 확정했다(4절).

| 항목 | 값 | 위치 |

| 클라이언트 | `ai.client=fake`(기본), 키가 있는 환경만 `claude` | `application.yml` |

## 2. 파라미터 근거
- **effort `LOW`:** 하는 일이 문장에서 메뉴·조건을 찾고 목록에서 고르는 것이라 깊은 추론이 필요 없다. effort를 낮추면 생각에 쓰는 토큰과 응답 시간이 줄어든다. 평가에서 세 모델 모두 같은 옵션으로 호출이 실패하지 않았고, 출력은 호출 1건에 50~60토큰 수준이었다.
- **최대 토큰 4096:** 생각과 응답이 같은 한도를 나눠 쓴다. 응답 JSON은 수백 토큰이지만 한도가 너무 작으면 생각에서 다 써 응답이 잘린다. 잘리면(`max_tokens`) 응답 오류로 보고 `FALLBACK`으로 대체한다.
- **타임아웃 15초·재시도 2회:** 사용자가 기다리는 요청이라 오래 매달지 않는다. 실패하면 오류가 아니라 `FALLBACK`(직접 고르기 안내)으로 응답한다.
- **구조화 출력:** 응답 형태를 스키마로 강제해 JSON 파싱 실패를 없앤다. 값이 맞는지(레시피 ID·인분·조건 범위)는 서버가 다시 검증한다.
- **temperature 미지정:** 구조화 출력과 서버 검증으로 결과를 고정하므로 따로 정하지 않는다. 최신 Haiku는 기본값이 아닌 샘플링 값을 보내면 400을 돌려주므로, 모델을 바꿔도 같은 요청이 통하도록 보내지 않는다.
- **캐시:** 레시피 목록은 요청마다 같아 캐시 효과가 크다. 조건 추천의 후보 목록은 조건마다 달라 캐시를 걸면 저장 비용만 더 든다.

## 4. 비교 결과와 선택
`evaluation.md` 5절의 결과(2026-11-03, 모델별 문장 50개 1회 실행)를 바탕으로 정했다.

| 기준 | Opus | Sonnet | Haiku | 판단 |
| --- | --- | --- | --- | --- |
| 정답률 (장보기 / 조건) | 100% / 95% | 100% / **100%** | 100% / 80% | 장보기는 같고 조건 추천에서 차이가 남 |
| 응답 시간 p95 (장보기 / 조건) | 3.1초 / **6.7초** | **2.6초 / 2.9초** | 3.0초 / 3.1초 | Opus는 조건 추천 p95가 길어 사용자가 기다리는 화면에 부담 |
| 요청 1건 예상 비용 | 약 $0.0028 | 약 $0.0013 | 약 $0.00007 | 세 모델 모두 요청 1건에 몇 원 이하 |
| 지시 주입 문장 | 따르지 않음 | 따르지 않음 | 따름 | Haiku만 문장 속 지시를 조건으로 받아들임 |
| **선택** | | **`claude-sonnet-5-5`** | | |

- 비용은 측정한 입력·출력·캐시 읽기 토큰에 3절 가격을 곱한 추정이다. 캐시 읽기 단가는 입력 단가의 10%로 계산했고, 처음 한 번 드는 캐시 저장 비용은 뺐다. 실제 금액은 Anthropic 콘솔로 확인한다.

**선택 이유**
- **정확도:** 조건 추천 20문장을 모두 맞힌 모델은 Sonnet뿐이다. Opus와 Haiku는 말하지 않은 종류(한식)를 요리 구분으로 추론해 채웠고, Haiku는 지시 주입 문장도 따랐다.
- **속도:** p95가 세 모델 중 가장 짧다. Opus보다 비싼 모델이 더 정확하지도, 더 빠르지도 않았다.
- **비용:** Opus의 절반이고, 요청 1건에 약 2원 수준이라 회원별 1분 5회 제한 안에서 부담이 작다. Haiku는 훨씬 싸지만 정답률 차이를 감수할 만큼 속도 이득이 없었다.

**프롬프트 v3 재평가 후 다시 검토 (2026-11-04)**
- v3(`prompt-history.md`) 적용 후 세 모델 모두 50/50을 맞혔다. p95는 Haiku 2.2초·1.8초, Sonnet 1.9초·1.8초, Opus 2.4초·5.1초(장보기·조건)다.
- Haiku는 정확도·속도가 Sonnet과 같아졌고 비용은 약 1/20이지만, v1에서 조건 4건을 틀리고 지시 주입을 따랐으며 v3 결과는 1회 실행이다.
- Sonnet은 v1·v3 두 번 모두 만점으로 가장 안정적이고, 요청 1건 비용 차이(약 2원)가 서비스 규모에서 크지 않아 **Sonnet을 유지**한다.

**다시 검토할 조건**
- 운영 이력·지표에서 AI 비용이 문제가 되거나, 평가 문장을 늘려 여러 번 실행해도 Haiku가 Sonnet과 같은 정답률을 유지하면 Haiku 전환을 다시 검토한다.
- 평가는 모델별 실행 횟수가 적어 응답 시간은 참고값이다. 운영 지표(`recipick_ai_latency_seconds`)의 p95가 길어지면 다시 비교한다.
