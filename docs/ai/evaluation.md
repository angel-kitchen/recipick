# AI 평가

> 실제 Claude 응답의 정답률·응답 시간·토큰을 같은 문장으로 재서, 모델 선택(`model-selection.md`)과 프롬프트 개선(`prompt-history.md`)의 근거로 쓴다.

## 1. 평가 대상
AI가 직접 판단하는 부분만 잰다. 후보 거르기·인분 범위·중복 금지처럼 서버가 검증하는 부분은 기존 테스트가 확인한다.

| 기능 | 평가하는 호출 | 문장 수 | 파일 |
| --- | --- | --- | --- |
| AI 자연어 장보기 | `extractMenus` (메뉴·인분) | 30 | `src/test/resources/ai-eval/auto-cart-cases.json` |
| AI 조건 추천 | `extractConditions` (조건 5개) | 20 | `src/test/resources/ai-eval/recommend-cases.json` |
| AI 조건 추천 ③ | `recommendRecipes` (후보 안에서 고르기) | 14 | `src/test/resources/ai-eval/recommend-pick-cases.json` |
| AI 조건 추천 전체 흐름 | `extractConditions` → 서버 후보 거르기 → `recommendRecipes` | 60 | `src/test/resources/ai-eval/vague-cases.json` |

③ 후보 고르기는 "어느 레시피가 가장 잘 맞는가"의 정답이 하나로 정해지지 않아, 후보 이름만 보고 판단할 수 있는 문장만 둔다. 맞는 레시피가 있는 문장 7개(정답 목록 안에서만 골라야 함)와 없는 문장 7개(빈 목록이어야 함)로 프롬프트 v2의 "맞는 게 없으면 빈 목록" 효과를 잰다. 후보는 서버처럼 조건(종류·요리 구분)으로 거른 레시피다.

전체 흐름 평가는 "해장용", "두부", "파스타 ㄱㄱ"처럼 대충 쓴 문장에서 실패가 한 단계가 아니라 이어진 흐름(조건을 못 뽑음 → 후보 없음)에서 생겨 따로 둔다. Facade와 같이 ① 조건 정리 → ② `RecipeRecommendCondition`과 재료 빼기로 후보 거르기 → ③ 고르기를 재현하고 최종 추천으로 채점한다. 레시피 속성과 재료는 로컬 시드 SQL에서 읽는다.

| 띄어쓰기 오류 | "돼지 고기 빼고 볶음", "새우빼고파스타", "후딱한끼" | 띄어쓰기가 틀려도 조건·재료 빼기가 맞는지 |

## 3. 채점 기준
- **자연어 장보기:** 기대 메뉴 수와 레시피를 고른 메뉴 수가 같고, 메뉴마다 고른 레시피가 모두 허용 이름 안에 있으며 인분이 같으면 정답이다. 모호한 문장은 허용 이름을 여러 개 둔다. 목록에 없는 메뉴는 레시피를 하나도 고르지 않아야 정답이다.
- **조건 추천:** 다섯 조건(종류·요리 구분·최대 조리 시간·최대 맵기·제외 재료)이 모두 같아야 정답이다. 말하지 않은 조건을 채워도 틀린 것으로 본다.
- **조건 추천 ③:** 맞는 레시피가 없는 문장은 빈 목록이어야 정답이다. 있는 문장은 하나 이상 고르고, 고른 레시피가 모두 정답 목록 안에 있어야 정답이다. 관련 없는 레시피를 덧붙이거나 후보 밖 ID를 주면 틀린 것으로 본다.
- **전체 흐름:** 최종 추천이 하나 이상이고 모두 정답 목록 안에 있으면 정답이다. 정답 목록은 문장 뜻에 맞는 레시피를 넓게 둔다(예: "야식"은 19개). 레시피와 관계없는 문장("오늘 날씨 어때", "케이크 만들고 싶어")은 추천이 없어야 정답이다.
- 호출이 실패하면(시간 초과·거절 등) 틀린 것으로 센다.

## 4. 실행 방법
비용이 드는 실제 호출이라 평소 `./gradlew test`와 CI에서는 건너뛴다. 키가 있는 환경에서 아래처럼 실행한다.

```bash
printf "키 입력: " && read -rs ANTHROPIC_API_KEY && echo && export ANTHROPIC_API_KEY
AI_EVAL=true AI_EVAL_MODEL=claude-sonnet-5-5 ./gradlew test --tests '*ClaudeAiEvaluationTest' --rerun
unset ANTHROPIC_API_KEY
```

- 키는 명령어에 직접 쓰지 않고 `read -rs`로 화면에 보이지 않게 입력받는다. 명령어에 쓰면 셸 기록에 남는다.
- 입력 안내를 `read`의 옵션이 아닌 `printf`로 출력하는 것은 bash(`read -p`)와 zsh(`read "변수?안내"`)의 문법이 달라서다. 이 방식은 macOS(zsh)·Linux·Git Bash에서 모두 동작한다.
- `AI_EVAL_MODEL`을 바꿔 같은 문장으로 모델을 비교한다(기본값은 운영과 같은 `claude-sonnet-5-5`).
- `--rerun`이 없으면 Gradle이 이전 결과를 재사용해 다시 호출하지 않는다.
- 결과는 `build/ai-eval/{모델}-{시각}.md`에 문장별 정답 여부·AI 응답·응답 시간과 합계로 남는다. 같은 모델로 프롬프트만 바꿔 비교할 때는 `AI_EVAL_LABEL`(예: `recommend-v1`)을 주면 파일 이름에 붙는다.
- ③만 따로 돌릴 때는 `--tests '*ClaudeAiEvaluationTest.evaluateRecommendPicks'`, 전체 흐름만 돌릴 때는 `--tests '*ClaudeAiEvaluationTest.evaluateVagueRecommend'`로 실행한다.
- 키를 매번 붙여 넣지 않으려면 macOS 키체인에 저장하고 `ANTHROPIC_API_KEY="$(security find-generic-password -a "$USER" -s anthropic-api-key -w)"`로 꺼내 쓸 수 있다. 키는 화면·셸 기록에 남지 않는다.
- 한 번 실행에 문장 124개(장보기 30, 조건 20, ③ 후보 고르기 14, 전체 흐름 60)를 호출한다. 전체 흐름은 문장마다 최대 두 번 호출한다. Sonnet 기준 전체 흐름 60문장 한 번에 약 $0.4가 든다(프롬프트 v4, 프롬프트 캐시 적용. 캐시 전 약 $1.2). 5절의 모델 비교 표는 ③을 추가하기 전 장보기·조건 50개로 실행한 결과다. 429·5xx·연결 오류는 SDK가 최대 2번 재시도하므로 실제 호출은 더 늘 수 있다.
- 타임아웃(15초)·재시도(2회)·최대 토큰(4096)은 운영 기본값(`ClaudeProperties`)과 같게 둬, 운영에서 시간 초과될 응답은 평가에서도 실패로 센다.

- 기준선의 문장 수(58)는 평가 문장을 정리하기 전이다. 이후 "야식" 중복을 "안주"로 바꾸고 "요린이 요리", "애들도 만들 수 있는 거"를 더했다.
- v4는 조건이 없을 때 레시피 100개를 후보로 넘겨 입력 토큰이 요청 1건에 약 8,000개로 늘었다. 응답 시간은 평균 약 4.5초다.
- 프롬프트 캐시는 ③의 시스템 프롬프트(지시문 + 후보 목록)에 걸었다. 조건 없는 문장은 매번 같은 레시피 100개 목록을 보내 대부분 캐시 읽기(정가의 10%)로 처리됐고, 입력 비용이 약 $0.99 → $0.23(캐시 쓰기 추정 포함)으로 줄었다. 출력 비용(약 $0.20)은 그대로라 요청 1건은 약 $0.020 → $0.007이다. 응답 시간은 출력 생성이 대부분이라 거의 같다.
- 캐시 쓰기 토큰(정가의 125%)은 `AiUsage`에 남기지 않아 표에 없다. 레시피 100개 목록 약 8,000토큰을 몇 번 쓰는 정도라 비용에 주는 영향은 작다.
- 캐시 적용 뒤 52/60은 프롬프트가 같은데 결과가 바뀐 경우로, 캐시는 응답 내용에 영향을 주지 않는다. "술안주", "혼밥용", "헬창 식단"이 틀리고 "안주"가 맞아 경계에 있던 문장이 실행마다 바뀐 것이다. v4의 세 번 실행은 55·54·52로 2~3건 오르내린다.
- 같은 v4로 처음 실행했을 때(10:10)는 55/60이었지만, 조건 분석 평가가 20/20 → 18/20으로 떨어졌다. "국물이면 요리 구분을 채우지 않는다"는 규칙을 "국"에도 적용해 "반 시간 안에 되는 국"의 SOUP를 비웠다. 규칙을 "'국물'이라고만 하면"으로 좁히고 다시 실행한 결과가 위 표다.
