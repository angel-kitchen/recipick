# 탈퇴 휴대전화의 무료체험 차단

멤버십 이력(관리자 지급 포함)이 있는 회원의 탈퇴 시 휴대전화를 HMAC-SHA-256으로 변환해 `TRIAL_BLOCK`에 저장합니다. 원문과 회원 ID는 저장하지 않습니다. 차단 종료는 탈퇴 시각 + 1년이며 만료 시각부터 무료체험 자격을 제한하지 않습니다.

## 탈퇴 연결 계약

탈퇴 Facade의 쓰기 트랜잭션에서 첫 DB 작업으로 회원 행을 잠그고 탈퇴 가능 조건을 검사한 뒤, 개인정보를 대체하기 **전에** `trialBlockService.recordWithdrawal(memberId, withdrawnAt)`를 호출합니다. 기존 트랜잭션이 없거나 읽기 전용이면 거절합니다. 이 메서드는 탈퇴 자체를 수행하지 않습니다.

이용 이력이 없으면 새 기록을 만들거나 기존 기간을 연장하지 않습니다. 이용 이력이 있으면 원자적 upsert로 기존 만료 시각과 새 탈퇴 시각 + 1년 중 늦은 값을 저장합니다. 동일 번호의 중복 요청에도 한 행만 유지합니다. 마이페이지와 내 멤버십의 `trialEligible`은 현재 계정의 이용 이력이 없고 활성 차단도 없을 때만 true입니다.

## 키 설정

`TRIAL_BLOCK_HMAC_SECRET`에 Base64로 인코딩한 32바이트 이상의 별도 무작위 키를 설정합니다. JWT 키를 재사용하지 않습니다. 로컬 프로필만 설정을 생략할 수 있으며 `~/.recipick/trial-block-secret` 파일에 키를 생성·보존합니다. 로컬 경로는 `security.trial-block.local-key-path`로 변경할 수 있습니다.

운영의 모든 인스턴스에서 같은 키를 유지하고 안전하게 백업해야 합니다. 키를 변경하거나 잃으면 기존 해시와 대조할 수 없습니다. 키 교체 절차는 별도 설계가 필요합니다. 키와 휴대전화는 로그에 기록하지 않습니다.

## 만료 정리

기존 SchedulingConfig를 사용해 매일 04:10 KST에 만료 기록을 1,000건씩 별도 트랜잭션으로 삭제합니다. `expires_at <= 실행 시작 시각`인 행만 삭제하므로 여러 인스턴스의 중복 실행에도 결과가 동일합니다. 기간 연장과 삭제는 DB의 행 잠금으로 직렬화됩니다. 별도 분산 락은 사용하지 않습니다. 정리 전에라도 만료된 기록은 자격 판정에서 제외됩니다.

실제 탈퇴 API와 주문·환불 차단 확인, 개인정보 파기는 후속 작업입니다.
