# 유료 구독 시작 API

`POST /api/memberships/subscribe` — 회원 액세스 토큰과 `Idempotency-Key` 헤더 필수.

```json
{
  "autopayAgreed": true,
  "consentedAmount": 3900,
  "consentTextVersion": "v1"
}
```

프론트는 월 3,900원·첫 결제·월 자동갱신·해지 방법을 안내하고 동의받는다. 문구 버전은 공백 없이 1~20자이며 동의 시각은 서버에서 기록한다. 회원 ID나 결제 시각은 요청 본문으로 받지 않는다.

처리 결과는 HTTP 200, 공통 응답의 `data`에 다음 형태로 전달한다.

```json
{"membershipId": 123, "status": "IN_PROGRESS"}
```

| status | 화면 처리 |
| --- | --- |
| PAID | 첫 결제 확정·구독 완료. 내 멤버십을 다시 조회 |
| IN_PROGRESS | 처리 중. 같은 키와 같은 본문으로 재요청 |
| UNKNOWN | 결과 확인 중. 새 키로 청구하지 않고 같은 키로 확인하며 필요하면 운영 문의 |
| FAILED | 확정 실패 또는 이용권 반영 불가. 같은 키로 재청구하지 않음. 재구독은 새 키를 사용하되 미정산 환불이 있으면 완료 전까지 차단 |

200은 구독 활성화를 보장하지 않는다. 반드시 `status`를 확인한다. 오류는 기존 공통 오류 응답을 사용한다.

| HTTP | 코드 | 조건 |
| --- | --- | --- |
| 400 | COMMON-007 | 멱등 키 누락·빈 값 |
| 400 | COMMON-001 | 멱등 키 형식 오류 |
| 409 | COMMON-011 | 같은 키로 다른 동의 금액·버전 전송 |
| 400 | MEMBERSHIP-004 | 자동결제 미동의·잘못된 동의 정보 |
| 409 | MEMBERSHIP-002 | 활성·결제 대기·전환 대기 이용권 존재 |
| 409 | MEMBERSHIP-005 | 활성 결제 카드 없음 |
| 409 | MEMBERSHIP-009 | 미해결·미정산 결제 존재 |
| 503 | BILLING-009 | 기존 결제 기능 플래그가 꺼진 상태에서 신규 접수 |

회원 Facade는 `Propagation.NEVER`로 결제 `MembershipSubscriptionFacade.subscribe`(C-11)를 호출한다. 별도 회원 조회·잠금이나 트랜잭션을 먼저 열지 않는다. 결제의 접수 트랜잭션에서 회원 잠금이 첫 DB 작업이며, 접수 커밋 → PG 호출 → 결과 반영을 결제 도메인이 소유한다. 기존 키의 조회는 신규 청구 플래그가 꺼져도 가능하다.

키는 결제 계약에 따라 정규화하며 저장 시 회원 ID를 붙인다. 재요청의 서버 동의 시각은 멱등 해시에서 제외하고 최초 동의 기록을 유지한다. 회원 API가 중복 검사를 먼저 수행해 기존 요청을 막지 않는다.

신규 환경 변수·스키마 변경은 없다. API 연결만으로 운영 결제가 활성화되지는 않는다. 실제 PG 동작은 기존 결제 설정·키·기능 플래그에 따른다.

상세 결제 동작: [첫 결제 C-11 계약](membership-first-charge.md).


### 프론트 연결

`/membership`에서 월 3,900원·월 갱신·무료체험 종료 후 결제·해지 방법을 안내하고 동의받는다. 결제 결과 불명/처리 중 재확인은 같은 Idempotency-Key를 사용한다. 실제 PG 호출 검증과 운영 기능 스위치 활성화는 별도다.
