# 회원 탈퇴와 결제수단 정리

`POST /api/members/me/withdraw` — 회원 액세스 토큰 필요.

```json
{"password":"현재 비밀번호", "acknowledgedPointBalance":0}
```

확인 잔액은 필수이며 0 이상의 정수다. 프론트는 유효기간을 반영한 현재 사용 가능 잔액과 탈퇴 시 소멸을 안내하고 사용자가 확인한 값을 전달한다. 성공은 HTTP 204와 리프레시 쿠키 만료이며 응답 본문은 없다.

## 준비와 최종 탈퇴

1. Facade는 기존 Redis 세션 키를 확보한다.
2. 카드 정리 계약이 활성화되면 준비 Processor가 쓰기 트랜잭션의 첫 DB 작업으로 회원을 잠그고 비밀번호·진행 주문·활성/대기 이용권·정산 4 Scope 연결을 확인한다.
3. 결제 `WithdrawalPaymentMethodPreparer`가 미정산을 확인하고 카드 삭제 요청을 저장한다. 이 준비 단계에서는 포인트 소멸·장바구니 삭제·회원 파기를 하지 않는다. 원격 PG도 호출하지 않는다.
4. 준비 트랜잭션을 커밋한 뒤 PENDING·REVIEW_REQUIRED는 각각 409 BILLING-030·BILLING-031로 안내한다. 카드 삭제 요청은 유지된다. 정리 Worker가 PG 확인·삭제를 수행한다.
5. READY일 때 기존 최종 탈퇴 Processor를 별도 트랜잭션으로 호출한다. 회원부터 다시 잠그고 비밀번호·주문·이용권·모든 정산 조건과 포인트 확인 잔액을 다시 검증한다. 통과하면 포인트 소멸·장바구니 삭제·체험 차단·개인정보 정리를 같은 트랜잭션에서 수행한다.
6. 최종 커밋 후 이전 Redis 세션을 정리한다. 커밋 후 Redis 정리 실패에도 DB 탈퇴 상태·세션 버전으로 접근과 재발급을 차단한다.

준비와 최종 탈퇴 사이에 새 카드나 거래가 생기면 최종 검사에서 다시 거절한다. 원격 카드 정리는 독립적으로 완료되므로 이후 포인트 잔액 불일치 등으로 탈퇴가 거절돼도 원격 카드를 복구하지 않는다. 프론트는 **탈퇴 준비 중 저장 카드가 삭제될 수 있으며 탈퇴가 완료되지 않아도 다시 등록해야 할 수 있음**을 사전 안내한다.

## 화면 처리

| HTTP | 코드 | 처리 |
| --- | --- | --- |
| 204 | 없음 | 탈퇴 완료, 프론트 인증 정보 삭제 |
| 400 | MEMBER-005 | 현재 비밀번호 다시 확인 |
| 409 | MEMBER-006·MEMBER-007 | 진행 주문·활성/대기 이용권 먼저 처리 |
| 409 | BILLING-030 | 카드 정리 중. 완료 뒤 탈퇴를 다시 요청 |
| 409 | BILLING-031 | 카드 정리에 운영 확인 필요 |
| 409 | BILLING-004 | 미정산 멤버십 결제 존재 |
| 409 | POINT-002 | 최신 잔액을 조회해 사용자 재확인 후 재요청 |
| 409 | POINT-003 | 미정산 포인트 처리 대기 |
| 503 | MEMBER-008 | 필수 정산 영역 미연결 또는 카드 정리 스위치 비활성 |

위 코드는 대표 사례이며 상품 결제 정산·입력 형식·인증 오류는 기존 공통 계약을 따른다. 준비 결과를 트랜잭션 내부에서 예외로 바꿔 카드 삭제 접수를 롤백하면 안 된다. 최종 탈퇴 오류가 발생하면 그 최종 트랜잭션의 포인트·회원 변경은 모두 롤백된다.

## 활성화와 남은 범위

기존 `BILLING_KEY_DELETION_ENABLED`·`BILLING_KEY_DELETION_WITHDRAWAL_ENABLED`는 모두 기본 false다. 이번 회원 연결에서 운영 설정을 변경하지 않는다. 두 값이 모두 true여야 카드 준비와 AUTO_BILLING Scope가 활성화된다. 비활성 상태에서는 기존 최종 Processor의 Scope 검사로 탈퇴를 계속 차단한다.

운영 활성화는 결제·배포 담당이 원격 삭제 검증과 기존 DDL·설정 전달 절차를 확인한 뒤 별도로 진행한다. [카드 정리 계약](billing-key-cleanup.md)을 따른다. 장바구니는 삭제하고 담기 이력은 유지하며, 찜은 탈퇴 제한 조건이 아니며 이번 범위에서는 삭제하지 않는다.
