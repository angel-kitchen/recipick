# 조회수 증가가 레시피 상세 조회를 락 대기로 실패시킬 수 있었다

| 항목 | 내용 |
| --- | --- |
| 제목·담당자·발생일 | 레시피 조회수 증가의 락 대기 · 태헌 · 2026-11-03 |
| 영향 범위 | 레시피 상세 조회(`GET /api/recipes/{id}`). 관리자가 같은 레시피를 수정하는 동안 회원 조회가 `COMMON-010`으로 실패할 수 있었다. 머지 전 리뷰에서 발견했다 |
| 관련 이슈·PR·커밋 | #409, PR #423 |
| 처리 상태 | 해결(조회수 증가만 별도 트랜잭션). 같은 행에 몰리는 쓰기는 남은 제한 |

## 1. 증상

- 기대한 동작과 실제 동작: 상세 조회는 읽기 전용이라 락 대기와 상관없이 응답해야 한다. 최초 구현은 조회수 `UPDATE`를 상세 조회와 같은 트랜잭션에서 실행해 조회가 쓰기 트랜잭션이 됐다.
- 발견 경로: PR #423 팀 리뷰.
- 리뷰 지적 요지
  - `UPDATE`가 `RECIPE` 행에 X 락을 잡고 트랜잭션이 끝날 때까지 유지한다.
  - 관리자가 `findByIdForUpdate`로 같은 레시피를 잡고 저장(감사 로그 포함)하는 동안 회원 상세 조회가 대기하고, 길어지면 `COMMON-010`(락 대기 시간 초과)으로 실패할 수 있다.
  - 인기 레시피는 동시 조회가 같은 행 락에 줄을 선다.
- 재현: 두 요청을 동시에 보내 실제로 실패시켜 보지는 않았고, 락 동작을 근거로 판단했다.

## 2. 원인

| 가설 | 확인 방법 | 관찰 결과·판정 |
| --- | --- | --- |
| 조회수 `UPDATE`의 행 락이 상세 조회 전체 시간 동안 유지된다 | 서비스의 트랜잭션 경계 확인 | 조회와 증가가 한 트랜잭션이라 락이 응답이 끝날 때까지 유지됐다 |
| 관리자 수정과 락이 충돌한다 | 관리자 쪽 `findByIdForUpdate` 사용 확인 | 같은 행의 락이라 서로 대기한다 |

확인된 원인: 읽기 작업(상세 조회)에 쓰기(`UPDATE`)를 같은 트랜잭션으로 묶어서, 쓰기의 행 락 보유 시간이 조회 시간만큼 늘었다.

## 3. 해결

- 바꾼 내용과 이유: `RecipeFacade.getRecipe`가 읽기(`RecipeService.getRecipe`)를 끝낸 뒤 `RecipeService.increaseViewCount`를 별도 짧은 트랜잭션으로 호출한다. 행 락은 이 `UPDATE` 한 문장 동안만 잡는다. 증가가 실패하면 WARN 로그만 남기고 응답은 그대로 돌려준다.
- 함께 정한 규칙: 조회수는 카운터라 `updated_at`을 갱신하지 않는다. 관리자 화면의 `updatedAt`이 "마지막 조회" 시각이 되지 않도록 컨벤션에 예외를 추가했다(`docs/convention.md`).
- 다른 대안을 선택하지 않은 이유: 별도 테이블이나 비동기 이벤트는 구현 범위가 커서 이번에는 택하지 않았다. 리뷰도 최소한 락 보유 시간을 줄이는 방법을 먼저 제안했다.
- 변경 코드·설정·문서: [`RecipeFacade`](../../src/main/java/com/recipick/domain/recipe/facade/RecipeFacade.java), [`RecipeService`](../../src/main/java/com/recipick/domain/recipe/service/RecipeService.java), `docs/convention.md`
- 필요한 조치: 운영은 `ddl-auto: update`라 배포 때 `RECIPE.view_count`(기본값 0)와 인덱스가 자동으로 추가된다.

## 5. 재발 방지와 남은 작업

- 추가한 규칙: 카운터 증가는 `updated_at`을 갱신하지 않는다(컨벤션 예외).
- 남은 제한: 인기 레시피는 여전히 같은 행에 `UPDATE`가 몰린다. 조회수 조작(새로고침 반복)을 막는 중복 제거는 없다. 트래픽이 늘면 별도 테이블이나 비동기를 검토한다([상품 ADR](../adr/product-domain.md) 3-6, 4절).
- 공유할 적용 방법: 조회 API에 카운터 증가를 넣을 때는 읽기 트랜잭션과 분리하고, 실패해도 응답에는 영향을 주지 않게 한다.
