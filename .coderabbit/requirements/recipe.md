## 1차

### 일반 회원

- **회원 탈퇴** (담당: 보민 — 찜 등 레시피 도메인 데이터 정리 연동, 탈퇴 기능: 채빈)
    - 로그인한 회원이 비밀번호를 다시 입력(재인증)해 탈퇴
    - 결제 대기·취소 처리 중인 주문, 정상 진행 중인 배송 미완료 주문, 미해결 결제·환불, 활성 멤버십(해지 예약 포함)이 있으면 탈퇴할 수 없으며 먼저 처리하도록 안내
    - 취소·환불이 완료되어 종료된 주문과 배송 완료 주문은 탈퇴를 제한하지 않음. 다만 관련 미해결 결제·환불이 남아 있으면 탈퇴 불가
    - 탈퇴와 탈퇴 제한 상태를 새로 만드는 작업은 같은 회원 행을 잠가 경합을 제어하며, 탈퇴는 잠금 후 탈퇴 여부·진행 중 주문·미해결 결제·환불·활성 멤버십을 확인
    - 탈퇴하면 로그인·토큰 재발급을 차단하고 모든 기기의 리프레시 토큰을 폐기하며, 기존 액세스 토큰으로 요청해도 회원 인증 시 탈퇴 여부를 확인해 접근을 거절
    - 회원 정보의 이메일·이름·휴대전화는 고유한 대체값으로 바꾸고, 현재 배송지 선택과 이용 마트를 해제한 뒤 배송지를 삭제
    - 주문에 기록된 수령인·연락처·배송 주소와 결제·멤버십 기록은 회원 정보 정리와 별개로 보관하며, 항목별 보존 근거·기간과 만료 후 파기 방식은 별도로 확정
    - 장바구니·찜·포인트·결제수단 등 다른 도메인 데이터의 정리 범위는 해당 담당과 정하며, 탈퇴로 소멸되는 포인트 잔액은 탈퇴 전에 안내
    - 멤버십 이용 이력(관리자 지급 포함)이 있는 회원이 탈퇴하면 휴대전화의 키 해시(HMAC-SHA-256)를 TRIAL_BLOCK에 탈퇴 시각부터 1년간 보관
    - 같은 번호로 재가입하면 가입·유료 구독은 가능하지만 차단 기간 중에는 무료체험을 받을 수 없으며, 만료된 차단 기록은 체험 자격을 제한하지 않음
    - 차단 기간 중 이용 이력 없이 재가입·재탈퇴하면 기존 만료일을 유지하고, 새 계정에 멤버십 이용 이력이 있으면 새 탈퇴 시각부터 1년으로 연장
    - 해시 보관 항목·사유·기간은 탈퇴 화면과 개인정보처리방침에 표시하고, 만료된 기록은 내부 배치가 삭제
    - 회원 쪽 탈퇴 기반을 먼저 준비하되 주문·결제·포인트 등 필요한 연동과 경합 검증이 끝나기 전에는 탈퇴 기능을 제공하지 않음
- **레시피 검색·조회** (담당: 보민)
    - 레시피명·카테고리 검색
    - 기본 인분·재료·조리법·조리 시간 확인
    - 재료 필요량은 1인분 필요량 × 선택 인분으로 환산해 표시
    - 관련 유튜브 영상 표시
    - 자동 장보기 가능 여부 표시
- **레시피 찜** (담당: 보민)
    - 레시피 찜·찜 해제, 찜 목록 조회
    - 같은 레시피는 한 번만 찜 가능
    - 찜 중복은 `UNIQUE(member_id, recipe_id)`로 동시 요청까지 최종 방어
    - 찜 해제는 찜이 없어도 성공 처리(멱등)

### 유료 회원

> 유료 회원은 일반 회원 기능을 모두 포함하며, 체험 회원도 대상입니다. 자동 구성은 모두 **이용 마트의 상품·판매 단위·가격·재고**를 기준으로 계산합니다.
>

- **메뉴·인분 선택** (담당: 보민)
    - 한 번의 요청에서 여러 메뉴와 메뉴별 인분 선택
    - 메뉴는 1~5개, 인분은 메뉴별 1~10, 같은 레시피 중복 선택 불가
- **수량 계산** (담당: 보민)
    - 1인분 필요량 × 선택 인분으로 환산
    - 동일 재료 합산
    - 이용 마트에서 그 재료에 해당하는 상품을 찾아 선택
    - 상품 선택 기준: 구매 가능 상품 우선 → 총 구매금액 낮은 순 → 예상 잔량 적은 순 → 가격·용량이 같으면 상품명 가나다순
    - 선택한 상품의 판매 단위로 한 번만 올림
    - 수량은 `DECIMAL`·`BigDecimal`로 계산하고 올림은 `CEILING` 사용(0.5개 등 소수 오차 방지)
    - 재고 비교는 장바구니에 이미 담긴 같은 상품 수량 + 이번 추가 수량 기준
    - 예상 잔량(총 구매량 − 총 필요량)은 저장하지 않고 미리보기 시점에 계산
- **필수·선택 재료** (담당: 보민)
    - 필수 재료는 기본 포함
    - 고명 등 선택 재료는 기본 제외 후 사용자가 선택
- **자동 구성 미리보기** (담당: 보민)
    - 담기 전에 이용 마트 기준으로 표시
    - 재료별 필요량·연결 상품·구매 수량·예상 잔량·가격·구매 불가 사유
    - 전체 합계 가격 표시
    - 미리보기 요청은 `PREVIEWED` 상태로 저장하고 요청 번호 반환
    - 미리보기 다시 조회 시 `PREVIEWED`는 현재 가격·재고로 재계산, `CONFIRMED`는 확정 시점 결과 반환
    - 재료별 연결 상품 후보를 함께 보여 주고 사용자가 원하는 상품(브랜드)을 고를 수 있음
    - 확정하지 않은 `PREVIEWED` 요청은 생성 7일 후 배치로 정리
    - 정리할 요청에 연결된 AI 요청 이력은 지우지 않고, 같은 트랜잭션에서 이력의 요청 연결을 먼저 비운 뒤 요청을 삭제
- **구매 불가 사유** (담당: 보민)
    - 이용 마트 미판매(그 재료의 상품 없음)
    - 판매 중지
    - 품절
    - 재고 부족(장바구니에 담긴 수량 + 이번 구매 수량이 재고보다 많음)
- **자동 구성 확정** (담당: 보민)
    - 확정 시 서버가 이용 마트 기준으로 가격·재고·수량 재계산
    - 구매 가능한 상품만 장바구니에 추가
    - 추가한 상품은 담기 이력에 자동 담기 경로와 요청 번호로 기록
    - 한 요청은 한 번만 확정 — `PREVIEWED → CONFIRMED` 조건부 갱신으로 연타·재전송 시 중복 합산 방지
    - 미리보기 이후 이용 마트가 바뀌었으면 확정 거부 후 다시 미리보기 안내
    - 구매 가능한 상품이 하나도 없으면 장바구니에 담지 않고 안내
    - 미리보기와 확정 시점 합계가 다르면 가격 변경 안내
- **자동 구성 기록** (담당: 보민)
    - 요청별로 계산 기준 마트와 함께 저장
    - 선택 메뉴·인분·선택 재료, 재료별 계산 결과(필요량·선택 상품·구매 수량·가격), 구매 불가 재료
    - 실제 추가 상품은 담기 이력으로 확인

### 관리자

- **관리자 감사 로그** (담당: 보민 — 레시피·재료 기록 연동, 공통 감사 기능: 채빈)
    - 관리자가 수행한 등록·수정·삭제·상태 변경과 개인정보가 보이는 조회를 ADMIN_AUDIT_LOG에 기록
    - 기록 항목은 관리자·작업 종류·대상 종류와 ID·관련 마트·변경 전후 값(details)·접속 IP·기록 시각이며, 목록 조회의 대상 ID와 details는 비워 둘 수 있음
    - 내부 DB 변경은 작업과 감사 기록을 같은 쓰기 가능한 트랜잭션으로 처리하고 기록 실패 시 작업도 롤백
    - 개인정보가 보이는 조회도 조회와 감사 기록을 같은 쓰기 가능한 트랜잭션으로 처리하며, 기록에 실패하면 조회 결과를 반환하지 않음
    - 외부 결제사 호출이 필요한 관리자 작업은 요청 접수 상태와 감사 로그를 먼저 함께 저장·커밋한 뒤 외부 호출을 수행하고 최종 결과는 별도 트랜잭션으로 반영
    - 각 도메인은 global의 공통 기록 인터페이스 AdminAuditRecorder를 호출하고 구현은 회원 도메인이 제공하며, 원래 작업을 조립하는 위치에서 중복 없이 기록
    - details에는 필요한 변경 전후 값만 기록하고 기존 이력 표와 연결하지 않으며, 개인정보·비밀번호·비밀번호 해시·토큰·빌링키·비밀키는 넣지 않음
    - 조회 응답 본문·이메일·이름 검색어와 거절 사유 등 자유 입력 원문은 감사 로그에 복사하지 않음
    - 실제 변경이나 새 실행이 없는 쓰기 재요청은 기록하지 않고 개인정보 조회는 요청마다 기록
    - 환불 재처리는 새 실행을 시작하면 기록하되 같은 멱등 키의 재전송과 구분하며, 최종 기록 시점과 전달 항목은 결제 담당과 확정
    - 시스템 결제 만료·자동 취소 등 자동 처리는 별도의 관리자 행위로 기록하지 않음
    - 접속 IP는 서버가 직접 확인한 주소를 기본으로 하며, 배포 후에는 신뢰하도록 설정한 프록시가 정리해 전달한 헤더만 사용
    - 감사 로그는 추가만 가능하며 관리자 수정·삭제 API를 두지 않고, 생성 시각부터 1년이 지난 기록은 내부 배치가 삭제
    - 기록 대상
        - 회원·멤버십: 멤버십 지급, 회원 목록·회원별 멤버십 이력 조회
        - 마트·상품: 마트 등록·수정·운영 상태 변경, 카테고리 등록·수정·삭제, 상품 등록·수정·삭제·가격·판매 상태·재료 연결 변경, 관리자 수동 재고 조정
        - 레시피: 레시피 등록·수정·상태 변경, 레시피 재료 변경, 재료 등록·수정, 관리자의 자동 장보기 지정·해제
        - 주문: 주문 수락·거절·배송 상태 변경
        - 결제: 관리자 환불 재처리, 관리자 결제·포인트 조회
    - 슈퍼 관리자만 기간·관리자·작업 종류·대상 종류로 목록을 검색하고 상세를 조회
- **레시피 관리** (담당: 보민)
    - 레시피 100개(한식 70·양식 30) 등록·조회·수정·비활성화
    - 한식·양식, 요리 유형 설정
    - 기본 인분·조리 시간·난이도·맵기·조리 순서·유튜브 영상 관리
- **레시피 재료 관리** (담당: 보민)
    - 재료별 1인분 필요량과 g·ml·개 단위 등록
    - 필수·선택 재료 구분
    - 한 레시피에 같은 재료 중복 등록 불가 — `UNIQUE(recipe_id, ingredient_id)`
    - 단위는 재료(`INGREDIENT.unit`)에만 두고 레시피 재료는 재료 단위를 따름
    - 1인분 필요량은 0 초과, 소수 허용(`DECIMAL(10,2)`)
- **자동 장보기 지정** (담당: 보민)
    - 모든 필수 재료의 1인분 필요량·단위가 등록되고, 그 재료에 연결된 상품이 있는 레시피만 지정
    - 레시피 재료 변경으로 조건이 깨지면 자동 장보기 지정을 자동 해제
    - 관리자 레시피 목록에 "연결 상품 없는 필수 재료 수" 표시

## 2차

### 유료 회원

- **AI 자연어 장보기** (담당: 보민)
    - 문장(1~200자)에서 메뉴·인분을 추출해 자동 구성 미리보기 제공
    - 추출한 메뉴가 모두 자동 장보기 가능 레시피로 확인되면 바로 미리보기 생성
    - 일부 메뉴만 확인되거나 모호하면 미리보기를 만들지 않고, 확인된 메뉴와 후보를 보여 주고 사용자가 고르게 함
    - 결과는 오류가 아니라 상태로 응답: `PREVIEWED`(미리보기 생성), `NEEDS_SELECTION`(사용자 선택 필요), `NO_MATCH`(맞는 레시피 없음), `FALLBACK`(AI 장애로 레시피명 검색 결과 제공)
- **AI 조건 추천** (담당: 보민)
    - 문장(1~200자)에서 조건(종류·요리 구분·최대 조리 시간·최대 맵기·제외 재료)을 분석해 등록 레시피 100개 안에서 최대 5개 추천
    - 처리 순서: ① AI가 문장을 위 조건 항목으로 정리 → ② 서버가 조건 값을 검증하고 레시피 검색 조건으로 적용해 후보를 거름 → ③ AI가 그 후보 안에서만 고르고 추천 이유를 작성
    - AI 장애 시 대체(`FALLBACK`): ①에서 실패하면 결과 없이 조건으로 직접 검색하도록 안내, ③에서 실패하면 서버가 거른 후보 중 최대 5개를 추천 이유 없이 제공
    - 결과는 상태로 응답: `RECOMMENDED`, `NO_MATCH`(조건을 만족하는 레시피 없음), `FALLBACK`
- **AI 처리 기준** (담당: 보민)
    - AI는 메뉴·인분·조건만 분석
    - 재료량·수량·가격·재고·멤버십은 서버가 검증
    - AI가 고른 레시피는 서버가 존재·활성·자동 장보기 가능 여부를 다시 확인하고, 후보 밖 레시피는 결과에서 제외
        - AI 자연어 장보기: 메뉴 1~5개·인분 1~10·중복 금지도 확인
        - AI 조건 추천: 최대 5개까지만 남김
    - AI 호출은 DB 트랜잭션 밖에서 함
    - 외부 AI 서비스가 응답 지연·장애·요청 한도 초과로 실패하면 오류가 아니라 `FALLBACK`으로 응답하고 직접 레시피를 고르도록 안내(AI 자연어 장보기는 레시피명 검색 결과 제공, AI 조건 추천은 위 대체 기준)
    - 회원별 AI 요청은 1분에 5회로 제한하고, 초과하면 AI를 호출하지 않고 403 오류(`AI-001`)로 거절
    - 성공·실패 모두 요청 이력 저장(요청 유형, 원문, 분석 결과, 연결 레시피, 결과 상태, 모델, 입력·출력·캐시 토큰, 응답 시간, 실패 사유)
        - 성공 여부는 AI 응답을 받아 결과에 썼는지로 판단: `PREVIEWED`·`NEEDS_SELECTION`·`NO_MATCH`·`RECOMMENDED`는 성공, `FALLBACK`은 실패(실패 사유 기록)
        - AI 조건 추천은 두 번 호출한 토큰·응답 시간을 합산
        - 회원별 한도 초과로 거절한 요청은 AI를 호출하지 않으므로 이력을 남기지 않음

### 관리자

    - `SUPER_ADMIN` 전용

    - 사용자 입력 원문을 보는 조회라 관리자 감사 로그에 기록
