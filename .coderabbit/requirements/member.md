## 1차

### 일반 회원

- **회원가입·로그인** (담당: 채빈)
    - 이메일 기반 일반 회원 가입·로그인
    - 가입 시 이름·휴대전화 입력, 이메일·휴대전화 중복 불가
    - 서비스 이용약관·개인정보 수집 동의 필수, 동의 일시 저장
    - 로그인 3회 연속 실패 시 10분 잠금
    - 액세스 토큰 30분, 리프레시 토큰 14일(HttpOnly 쿠키, Redis 저장), 로그아웃 시 폐기
    - 관리자는 별도 로그인
    - 본인의 장바구니·주문·결제·포인트 정보만 접근
- **비밀번호 변경** (담당: 채빈)
    - 로그인한 회원이 현재 비밀번호를 확인한 뒤 새 비밀번호로 변경
    - 새 비밀번호는 가입 때와 같은 규칙(8~20자, 영문·숫자·특수문자 포함, 공백 불가)으로 검증
    - 현재 비밀번호가 맞지 않으면 변경하지 않음
    - 변경하면 모든 기기의 리프레시 토큰을 폐기해 토큰 재발급을 차단하고, 이미 발급된 액세스 토큰은 만료(30분)까지 사용할 수 있음
    - 비밀번호 변경은 회원 행을 잠근 뒤 처리하고, 비밀번호 해시와 리프레시 세션 버전을 같은 DB 트랜잭션에서 변경해 동시 로그인·재발급의 이전 버전 토큰도 무효화
    - 변경 전 Redis 세션 키 목록을 확보하고 DB 커밋 뒤 해당 키만 정리하며, 정리가 실패하거나 늦게 저장된 이전 세션이 남아도 버전 검사로 재발급을 거절. 남은 키는 TTL로 만료
    - 비밀번호 오류·입력 검증 실패 시 비밀번호와 세션 버전을 변경하거나 Redis 세션을 삭제하지 않음
- **회원 탈퇴** (담당: 채빈 — 탈퇴 기능·회원 정보 정리·체험 차단)
    - 로그인한 회원이 비밀번호를 다시 입력(재인증)해 탈퇴
    - 결제 대기·취소 처리 중인 주문, 정상 진행 중인 배송 미완료 주문, 미해결 결제·환불, 활성 멤버십(해지 예약 포함)·결제 대기 유료 이용권·전환 대기 체험 이용권이 있으면 탈퇴할 수 없으며 먼저 처리하도록 안내
    - 탈퇴 정산 확인은 3차까지 포함해 상품 결제(결과 불명·SYSTEM 환불·수동 확인), 멤버십 결제(구독·갱신·재시도·결과 불명·이용료 환불), 포인트(잔액 사전 안내·미정산 내역·소멸 처리), 자동결제(탈퇴 후 신규 청구 방지·결제수단 처리)를 확인 범위로 함
    - 각 영역의 실제 상태 판정과 정리 방식은 담당자와 합의해 연결하며, 일부 영역만 연결되거나 확인에 실패하면 탈퇴를 허용하지 않음. 장바구니·찜의 정리 계약도 별도로 확정
    - 외부 결제수단 정리가 필요하면 회원 잠금 트랜잭션 밖에서 별도 절차로 처리하고, 이미 시작된 거래의 후속 처리에는 탈퇴 검사를 추가하지 않음
    - 취소·환불이 완료되어 종료된 주문과 배송 완료 주문은 탈퇴를 제한하지 않음. 다만 관련 미해결 결제·환불이 남아 있으면 탈퇴 불가
    - 탈퇴와 탈퇴 제한 상태를 새로 만드는 작업은 같은 회원 행을 잠가 경합을 제어하며, 탈퇴는 잠금 후 탈퇴 여부·진행 중 주문·미해결 결제·환불·활성 멤버십을 확인
    - 탈퇴하면 로그인·토큰 재발급을 차단하고 모든 기기의 리프레시 토큰을 폐기하며, 기존 액세스 토큰으로 요청해도 회원 인증 시 탈퇴 여부를 확인해 접근을 거절
    - 회원 정보의 이메일·이름·휴대전화는 고유한 대체값으로 바꾸고, 현재 배송지 선택과 이용 마트를 해제한 뒤 배송지를 삭제
    - 주문에 기록된 수령인·연락처·배송 주소와 결제·멤버십 기록은 회원 정보 정리와 별개로 보관하며, 항목별 보존 근거·기간과 만료 후 파기 방식은 별도로 확정
    - 장바구니·찜·포인트·결제수단 등 다른 도메인 데이터의 정리 범위는 해당 담당과 정하며, 탈퇴로 소멸되는 포인트 잔액은 탈퇴 전에 안내
    - 탈퇴 전 실제 사용 가능 포인트를 안내하고, `POST /api/members/me/withdraw`에 `password`와 사용자가 확인한 `acknowledgedPointBalance`(필수, 0 이상의 Long, 잔액이 없으면 0)를 전달
    - 회원 쪽은 확인 잔액을 기본값으로 대체하지 않고 `WithdrawalSettlementChecker.requireSettled(memberId, acknowledgedPointBalance)`에 그대로 전달. POINTS 구현이 회원 잠금 이후 포인트를 잠그고 지연 만료·미정산 확인·실제 잔액 비교·소멸을 수행하며 다른 Scope는 확인 잔액을 사용하지 않아도 됨
    - 잔액만 있으면 탈퇴를 막지 않고 안내한 잔액과 실제 잔액이 같을 때 소멸 처리. 다르면 POINT-002(409)로 거절해 최신 잔액을 재확인하며 예외 시 지연 만료를 포함한 해당 트랜잭션 변경을 모두 롤백. 재안내용 잔액 조회도 유효기간을 반영
    - 포인트의 PENDING 적립·RESERVED 사용은 POINT-003(409)으로 탈퇴 차단. 포인트 잔액과 적립 원장의 합계가 맞지 않는 상태는 회원이 해결할 수 없는 문제라 409가 아닌 내부 오류(COMMON-500)로 차단하고 운영이 확인. CONFIRMED 사용 자체와 완료 이력만으로 차단하지 않으며 잔액이 0이어도 미정산 검사를 수행
    - 포인트 탈퇴 소멸은 자연 만료와 구분해 FORFEITED·WITHDRAWAL_FORFEITED로 기록하고 소멸 금액이 없으면 소멸 이력을 생성하지 않음(포인트 구현: 정윤)
    - 실제로 활성화된 멤버십 이용 이력(관리자 지급 포함, activated_at이 있는 이력)이 있는 회원이 탈퇴하면 휴대전화의 키 해시(HMAC-SHA-256)를 TRIAL_BLOCK에 탈퇴 시각부터 1년간 보관
    - 같은 번호로 재가입하면 가입·유료 구독은 가능하지만 차단 기간 중에는 무료체험을 받을 수 없으며, 만료된 차단 기록은 체험 자격을 제한하지 않음
    - 차단 기간 중 이용 이력 없이 재가입·재탈퇴하면 기존 만료일을 유지하고, 새 계정에 멤버십 이용 이력이 있으면 새 탈퇴 시각부터 1년으로 연장
    - 해시 보관 항목·사유·기간은 탈퇴 화면과 개인정보처리방침에 표시하고, 만료된 기록은 내부 배치가 삭제
    - 회원 쪽 탈퇴 기반을 먼저 준비하되 주문·결제·포인트 등 필요한 연동과 경합 검증이 끝나기 전에는 탈퇴 기능을 제공하지 않음
- **이용 가능 지역 판정** (담당: 채빈)
    - 현재 배송지의 법정동이 서비스 지역이면 그 지역의 마트를 이용 마트로 지정하고, 아니면 이용 마트 없음
    - 서비스 범위는 법정동 단위(지역당 마트 1곳)로 제한하며, 반경(2km) 기준은 구현 완료 후 도입
    - 위치 이용 동의 후 현재 위치로 주소를 설정하거나, 위치 거부·실패 시 주소를 직접 입력
    - 가입 전에 위치 동의와 주소 설정(핀 확정, 상세 주소 입력)을 먼저 받고, 서비스 가능 여부를 비로그인으로 확인한 뒤 가입·로그인 이후 배송지로 저장(위치 우선 가입 흐름)
    - 서비스 가능 지역 확인은 로그인 없이 호출할 수 있으며, 법정동 코드를 받아 가능 여부와 마트 이름만 응답하고 아무것도 저장하지 않음
    - 범위 밖이면 이용 불가 안내
    - 현재 위치 자체는 저장하지 않고 위치 동의 일시와 확정한 배송지, 이용 마트만 저장
    - 위치 이용에 처음 동의한 시각을 기록하며, 이후 배송지를 추가해도 기존 동의 시각을 덮어쓰지 않음
- **배송지 관리** (담당: 채빈)
    - 회원당 배송지를 여러 개 저장·수정·삭제하고, 이 중 1개를 현재 배송지로 선택(최대 5개)
    - 배송지는 명칭(선택)·주소·상세 주소(필수)·법정동 코드를 저장(위·경도는 저장하지 않음)
    - 본인 배송지만 조회하며, 현재 배송지를 먼저 표시하고 나머지는 최근 등록순으로 표시
    - 저장된 배송지가 없으면 빈 목록으로 표시
    - 배송지별로 해당 주소를 선택했을 때 서비스 이용이 가능한지 표시. 현재 이용 마트와 다른 지역도 운영 중인 마트가 있으면 이용 가능으로 안내
    - 첫 배송지는 자동으로 현재 배송지가 되며, 현재 배송지는 삭제할 수 없음
    - 현재 배송지를 삭제하려면 다른 배송지를 먼저 선택해야 하며, 삭제 후 나머지 배송지·현재 배송지·이용 마트는 유지
    - 새 배송지를 현재 배송지로 선택하지 않고 추가하면 기존 현재 배송지와 이용 마트를 유지
    - 배송지는 보낸 항목만 수정하며, 주소·상세 주소·법정동 코드는 함께 변경하고 명칭은 삭제 가능
    - 현재 배송지를 수정하면 이용 마트를 다시 판정하고, 다른 배송지를 수정하면 현재 배송지와 이용 마트는 유지
    - 이미 현재 배송지인 주소를 다시 선택해도 마트 운영 상태를 다시 판정하여 이용 마트를 갱신
    - 현재 배송지가 이용 마트를 결정하고, 현재 배송지를 바꾸면 이용 마트를 다시 판정(마트가 바뀌면 장바구니의 이전 마트 상품은 삭제하기 전에는 주문할 수 없음)
    - 동시에 배송지를 등록해도 최대 5개를 넘지 않으며, 처음 등록하는 배송지의 자동 선택은 한 건만 적용
    - 배송지 등록에 실패하면 기존 배송지 선택·이용 마트·위치 동의 기록은 변경하지 않음
    - 핀 위치가 입력한 주소와 다르면 경고 후 핀 기준으로 주소를 갱신하고 상세 주소를 다시 입력
    - 서비스 지역 밖 주소도 저장할 수 있고, 현재 배송지로 선택하면 이용 마트 없이 이용 불가 안내
    - 배송지 목록을 조회하는 것만으로 현재 배송지나 이용 마트를 변경하지 않음
    - 수령인 이름·연락처는 배송지에 저장하지 않고 주문마다 입력(기본값은 회원 이름·연락처)
- **마이페이지** (담당: 채빈 화면 구성, 각 도메인 조회 제공)
    - 내 정보(이메일·이름·휴대전화(원문)·이용 마트·현재 배송지·멤버십 유형·만료일·무료체험 가능 여부)
    - 비밀번호 변경과 회원 탈퇴를 제공
    - 지정된 마트가 운영 중지여도 마트 정보는 표시하고, 현재 배송지의 이용 가능 여부는 별도로 안내
    - 현재 배송지 지역의 운영 마트와 지정 마트가 같을 때만 이용 가능으로 표시하며, 불일치하거나 지정 마트가 없으면 이용 불가 안내
    - 정보 조회만으로 저장된 배송지나 이용 마트를 변경하지 않음
    - 멤버십 혜택은 activated_at이 있고 활성화·시작 시각 이상이며 유예 종료 시각(없으면 이용 종료 시각) 미만이고 즉시 종료되지 않았을 때 제공. 결제 대기·전환 대기는 혜택이 없음
    - GET /api/memberships/me는 활성 이용권이 없으면 pending에 결제 대기(PAYMENT_PENDING)·전환 대기(CONVERSION_PENDING)를 반환. pending은 이용권 ID·유형·발급 경로·상태·시작/종료·자동갱신·해지 예약 시각을 포함하며 없으면 null
    - 멤버십은 이용 기간과 즉시 종료 여부를 기준으로 표시하며, 자동갱신을 해지 예약해도 남은 이용 기간에는 혜택 유지
    - 무료체험 가능 여부는 관리자 지급을 포함해 실제로 활성화된 멤버십 이용 이력이 없고, 휴대전화가 탈퇴 전 이력으로 차단 기간 중이 아닌 회원에게만 가능으로 표시
    - 주문 내역, 결제 내역, 취소·환불 내역을 한 화면에서 제공
- **멤버십 기능 제한** (담당: 채빈)
    - 자동 장바구니·AI 요청 시 멤버십 안내
    - 상품 검색·직접 장바구니·주문·결제는 이용 가능

### 유료 회원

> 유료 회원은 일반 회원 기능을 모두 포함하며, 체험 회원도 대상입니다. 자동 구성은 모두 **이용 마트의 상품·판매 단위·가격·재고**를 기준으로 계산합니다.
>

- **멤버십 활성 검증** (담당: 채빈)
    - 요청 시 서버에서 활성 여부와 유형(일반·체험·유료) 판정
    - 내 멤버십에서 현재 이용권의 유형·발급 경로·이용 기간·자동갱신·해지 예약과 무료체험 가능 여부를 확인
    - 시작 시각부터 종료 직전까지 혜택을 적용하며, 해지 예약은 남은 기간의 혜택을 유지하고 즉시 종료된 이용권은 제외
    - 주문 생성 시 getTypeAt(memberId, 기준시각)으로 혜택 유형을 판정해 적립률을 주문에 저장. 활성화·이용 기간·실제 종료 시각을 고려하되 과거 유예 이력 전체를 재현하는 조회 계약은 제공하지 않음
    - 해지 예약·환불 종료는 grace_end_at을 비우므로 이후 getTypeAt으로 과거 유예 구간을 다시 조회한 결과는 달라질 수 있음. 기존 주문의 적립률은 저장된 스냅샷을 사용하며 현재 멤버십으로 재계산하지 않음

    - 개인정보가 보이는 조회도 조회와 감사 기록을 같은 쓰기 가능한 트랜잭션으로 처리하며, 기록에 실패하면 조회 결과를 반환하지 않음

    - 각 도메인은 global의 공통 기록 인터페이스 AdminAuditRecorder를 호출하고 구현은 회원 도메인이 제공하며, 원래 작업을 조립하는 위치에서 중복 없이 기록
    - details에는 필요한 변경 전후 값만 기록하고 기존 이력 표와 연결하지 않으며, 개인정보·비밀번호·비밀번호 해시·토큰·빌링키·비밀키는 넣지 않음

    - 실제 변경이나 새 실행이 없는 쓰기 재요청은 기록하지 않고 개인정보 조회는 요청마다 기록
    - 환불 재처리는 새 실행을 시작하면 기록하되 같은 멱등 키의 재전송과 구분하며, 최종 기록 시점과 전달 항목은 결제 담당과 확정
    - 시스템 결제 만료·자동 취소 등 자동 처리는 별도의 관리자 행위로 기록하지 않음
    - 접속 IP는 서버가 직접 확인한 주소를 기본으로 하며, 배포 후에는 신뢰하도록 설정한 프록시가 정리해 전달한 헤더만 사용
    - 감사 로그는 추가만 가능하며 관리자 수정·삭제 API를 두지 않고, 생성 시각부터 1년이 지난 기록은 내부 배치가 삭제

    - 감사 로그 조회는 GET /api/admin/audit-logs 및 /api/admin/audit-logs/{id}로 제공. 기간은 한국 시간 from 포함·to 미포함이며 생성 시각·ID 내림차순으로 페이지 조회(기본 20개, 최대 100개)

    - 관리자 이용권 지급은 1차 시연·테스트용이며, 3차 구독 결제·자동갱신 구현 완료 후 테스트용으로 유지하거나 제거할 예정
    - 슈퍼 관리자만 테스트 회원에게 지급 시점부터 30일 이용권을 지급하며, 결제·자동갱신 없이 지급 관리자와 생성 시각을 기록

    - 만료·즉시 종료 이력만 있는 회원은 다시 지급할 수 있고, 지급 이력은 무료체험 가능 여부에 반영
    - 슈퍼 관리자만 회원 목록에서 이메일·이름 부분 검색, 현재 활성 이용권 기준 멤버십 유형·발급 경로와 활성 여부 필터, 페이지·정렬을 사용해 회원별 유형·기간·체험 사용 이력을 조회하며 탈퇴한 회원은 제외
    - 회원 검색 조건은 함께 적용(AND)하며, 멤버십 유형·발급 경로는 현재 활성 이용권 기준으로 함께 검사. 비활성 필터와 유형·발급 경로를 동시에 지정하면 일치하는 회원 없음
    - 체험 사용 이력은 실제 체험 이용권 이력으로 판단하며, 관리자 지급 이력만 있는 경우와 구분

### 유료 회원

- **유료 구독** (담당: 채빈)
    - 월 3,900원
    - 첫 결제 성공을 확인한 뒤에만 유료로 전환
    - 첫 결제일이 월 갱신 기준일
- **무료체험** (담당: 채빈)
    - 회원 쪽 생성은 MembershipTrialService에서 동의 금액 3,900원·문구 버전·서버 동의 시각을 확인하고, 활성·대기 이용권·실제 활성화 이력·전화번호 체험 차단을 검사한 뒤 시작/활성화 시각부터 정확히 7일의 TRIAL 이용권을 생성
    - 자동갱신은 켜고 초기 청구·유예·월 갱신 기준일은 두지 않음. 동의 시각은 클라이언트 입력이 아니라 요청 처리 시 서버가 정한 시각을 기록
    - 생성 서비스는 쓰기 가능한 바깥 트랜잭션(MANDATORY) 전용. 최종 Facade의 첫 DB 작업은 회원 잠금이며 활성 카드와 미해결 결제를 검사한 뒤 호출. 미해결 결제 조회 계약 연결 전에는 Controller·신규 시작 API를 공개하지 않음
    - 이용 이력이 없는 회원은 계정당 1회 7일
    - 동일 휴대전화 번호의 중복 가입을 제한하고, 탈퇴 전 멤버십 이용 이력이 있는 번호는 탈퇴 후 1년간 무료체험을 제한(휴대전화 본인 인증이 없어 사람 단위의 완전한 차단은 아님)
    - 시작 시 청구 없음
    - 종료 시 첫 결제가 성공하면 유료 전환
    - 실패하면 일반 회원 전환 후 카드 변경·재구독 안내
- **해지 예약** (담당: 채빈)
    - 체험: 첫 자동 결제 중단, 남은 체험 기간 유지 후 일반 전환
    - 유료: 다음 자동 결제 중단, 결제한 기간 유지 후 만료 시 일반 전환
    - `POST /api/memberships/{membershipId}/cancel-reservation`로 본인의 활성 체험·구독·체험 전환 이용권과 결제 대기 유료·전환 대기 체험 이용권에 해지 예약하며 요청 본문은 없음
    - 회원 행을 첫 DB 작업으로 잠그고 탈퇴 여부를 검사한 뒤 지정 이용권을 소유 회원 조건으로 잠가 확인·변경. 타인·없는 이용권과 해지 예약 대상이 아닌 미시작·만료·즉시 종료 이용권은 `MEMBERSHIP-006`, 관리자 지급 이용권은 `MEMBERSHIP-007`로 거절
    - `autoRenew=false`와 최초 `cancelReservedAt`을 반영하고 grace_end_at은 null로 비우며 이용 기간·유형·발급 경로·월 갱신 기준일·결제 동의·즉시 종료 시각은 유지. 활성 기간 안의 재요청·동시 요청은 최초 예약 시각을 유지하며 성공
    - 성공 시 이용권 ID·변경 후 상태·자동갱신 여부·이용 종료 시각·해지 예약 시각을 응답. 정상 이용기간에는 CANCEL_RESERVED로 남은 혜택을 유지하고, 결제 대기는 PAYMENT_PENDING 유지, 전환 대기·유예 중 해지 예약은 EXPIRED로 혜택 종료. 유예 중 예약 화면에는 즉시 종료됨을 안내
    - 이용권 ID를 지정하므로 종료된 이전 이용권의 재요청이 이후 생성된 이용권을 해지하지 않음. 포트원·환불·빌링키 변경과 관리자 감사 기록은 수행하지 않음
    - 자동청구 대상에서는 예약된 이용권을 제외해야 하며 실제 청구·재시도 경합은 결제 담당과 별도 연동·검증(회원 API만으로 이미 시작된 외부 결제의 취소를 보장하지 않음)
    - 청구 접수와 해지 예약은 회원 → 이용권 순서로 같은 행을 잠가 순서를 정함. 청구는 잠금 후 자동갱신·해지 예약·동의 상태를 재확인하고, 이용권·이용기간별 회차와 회차·시도 번호별 시도 및 해당 시도의 고정 PG 결제 식별자(portonePaymentId)를 접수와 함께 저장·커밋한 뒤 PG 호출. 회차와 시도를 구분해 갱신의 명확한 실패 재시도를 금지하지 않음
    - 해지 예약보다 청구 접수가 먼저 확정됐다면 해당 시도는 진행. 성공하면 이번 결제 이용기간을 적용하되 해지 예약과 autoRenew=false를 유지해 다음 갱신부터 중단
    - 해지 예약보다 먼저 접수된 청구가 명확히 실패하면 추가 청구 재시도 없이 해당 시도를 종료하되 이미 남은 이용기간은 유지. 접수 커밋 후 중단돼도 기존 회차·시도와 고정 PG 결제 식별자를 복구 기준으로 사용하고, 중단만을 이유로 새 시도·새 식별자를 만들지 않음
    - 기존 시도가 READY이면 결제 도메인의 선점 절차로 같은 시도를 이어서 실행하며, 발송 여부나 결과가 불명확한 DISPATCHING·UNKNOWN·MANUAL_REVIEW는 기존 PG 결제 식별자로 결과를 재조회. 재조회 전 새 결제 호출·새 시도·새 식별자 생성으로 복구하지 않으며, PG 재호출 허용 여부는 결제 도메인의 확정 상태 전이·멱등 정책과 검증에 따름
- **즉시 해지** (담당: 채빈, 환불 처리: 정윤)
    - 유료 멤버십 회원은 이용기간 중 즉시 해지 및 환불을 요청할 수 있습니다.
    - 즉시 해지 요청 API는 멤버십 도메인이 소유합니다.
    - 요청 시 `Idempotency-Key`를 필수로 받고 결제 도메인의 이용료 환불 서비스를 호출합니다.
    - 환불 처리 중에는 멤버십을 `ACTIVE`로 유지합니다.
    - 환불이 `COMPLETED`된 경우에만 멤버십을 즉시 종료합니다.
    - 환불이 명확히 실패하면 멤버십을 `ACTIVE`로 유지합니다.
    - 환불 결과가 불명확하면 `REQUESTED` 상태와 멤버십 `ACTIVE`를 유지하고 웹훅·재조회로 결과를 확인합니다.
    - 결과 불명 건이 나중에 환불 성공으로 확인되면 `즉시 해지 환불 완료 반영`을 통해 멤버십을 종료합니다.
    - 같은 `Idempotency-Key`로 다시 요청하면 새 환불을 만들지 않고 기존 결과를 반환합니다.
    - 같은 이용권에 결과 확인 중인 `REQUESTED` 환불이 있으면 다른 키의 새 요청은 거절합니다.
    - 명확한 실패가 `FAILED`로 확정된 뒤에는 새 `Idempotency-Key`로 다시 요청할 수 있습니다.
- **결제 결과에 따른 전환** (담당: 채빈)
    - 결제 연동은 MembershipBillingService의 공개 계약과 DTO(BillingMembershipData, MembershipConsent, MembershipBillingTarget, MembershipBillingResult)로 제공하며 엔티티를 다른 도메인에 반환하지 않음
    - 변경 계약은 쓰기 가능한 바깥 트랜잭션(MANDATORY) 안에서만 실행. 호출자는 회원 → 빌링키 → 이용권 PK → 결제 회차 → 시도 → 환불 순서로 필요한 행을 잠그고 소유권·현재 회차·반영 여부를 검사하며 과거·확정 회차 결과는 반영 계약에 전달하지 않음
    - 웹훅·복구 경로는 잠금 트랜잭션 진입 전 findMemberIdOfMembership(membershipId)로 소유 회원 ID를 잠금 없이 읽고, 없으면 MEMBERSHIP-006으로 처리. 만료·종료 이용권과 탈퇴 회원의 이용권도 매핑 조회에 포함하며 이후 쓰기 트랜잭션에서는 회원 잠금부터 기존 소유권·상태 검사를 수행
    - 이용권 잠금·전체 ID·차단 여부·커서 기반 전환/갱신 대상 조회, 결제 대기 구독/전환 생성, 첫 결제 성공/실패·갱신 성공/중단·카드 없는 전환 종료·환불 완료 반영을 제공. 계약 내부에서 현재 시각이나 외부 PG 호출을 만들지 않음
    - 이미 반영됨·상태 충돌은 결과 enum으로 반환하며 예외는 호출자에게 전파해 결제 결과 기록과 함께 롤백. 결제 대기 유료의 임시 이용 기간·기준일은 첫 결제 성공 시 PG 결제 시각으로 교체
    - 갱신은 종료 시각을 줄이지 않고 해지 예약·자동갱신 중단을 되돌리지 않음. 전환 접수 시 체험 행의 autoRenew만 false로 바꾸고 별도 유료 행을 만들어 체험 이력을 보존
    - 미해결 결제로 구독·지급·체험을 거절할 오류는 MEMBERSHIP-009(409), 진행 중 결제로 즉시 해지를 보류할 오류는 MEMBERSHIP-010(409). 결제 도메인 실제 호출 연결은 후속 작업
    - 갱신 최종 실패는 자동갱신을 중단하되 유예 종료 시각까지 혜택을 유지하고 이후 일반 전환. 체험 종료 시 카드가 없으면 결제 없이 일반 전환
    - 즉시 해지 환불이 `COMPLETED`된 경우에만 유료 멤버십 종료
    - 같은 요청 안에서 환불 완료가 확인되면 멤버십 도메인이 즉시 종료
    - 결과 불명 후 나중에 성공이 확인되면 결제 도메인의 `즉시 해지 환불 완료 반영` 계약을 통해 종료
    - 환불액이 0원인 경우에도 `COMPLETED` 처리 후 멤버십 종료
- **자동 결제 동의** (담당: 정윤 안내, 채빈 저장)
    - 체험·유료 구독 시작 전 결제 금액·첫 결제일·월 갱신 주기·자동갱신 해지·즉시 해지 방법 안내
    - 동의 금액·동의 문구 버전·동의 일시를 멤버십에 저장
    - 자동 청구 시 멤버십 도메인에 자동청구 대상·동의 여부 확인

### 관리자

- **회원별 멤버십 이력 조회** (담당: 채빈)
    - `SUPER_ADMIN` 전용
    - 회원의 모든 이용권(체험·유료 전환·구독·관리자 지급)과 상태(이용 중·해지 예약·만료·즉시 해지·결제 대기·전환 대기) 조회
    - `GET /api/admin/members/{memberId}/memberships`로 조회하며 `page`는 0부터(기본 0), `size`는 1~100(기본 20), 등록 시각·ID 내림차순으로 정렬
    - 이용권 ID·유형·발급 경로·상태·이용 기간·자동갱신·월 갱신 기준일·해지 예약/즉시 종료 시각·지급 관리자 ID·등록 시각을 응답하고 개인정보·결제수단 정보는 포함하지 않음
    - 상태는 조회 시점의 판정 규칙을 사용. 미활성 유료는 PAYMENT_PENDING, 체험 종료 후 전환 대기는 CONVERSION_PENDING으로 표시하고 활성화된 이용권의 이용 시작 전 이력은 status를 null로 응답
    - 이력이 없는 회원과 범위를 벗어난 페이지는 정상 빈 목록이며 없는 회원·탈퇴 회원은 기존 회원 조회와 같이 `MEMBER-001`로 거절
    - 매 조회를 `MEMBER_MEMBERSHIP_HISTORY_VIEW`로 기록(대상은 회원 ID, 관련 마트는 현재 회원 마트, details는 비움)하며 조회와 감사 기록은 같은 쓰기 트랜잭션으로 처리하고 기록 실패 시 결과를 반환하지 않음
