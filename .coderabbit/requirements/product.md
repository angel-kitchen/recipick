## 1차

### 일반 회원

- **상품 검색·조회** (담당: 태헌)
    - 상품명 검색, 상세 조회
    - 카테고리·가격 범위로 필터링하고 가격순·최신순으로 정렬
    - 상품 카테고리 목록은 로그인 없이 조회(상품 필터 선택지)
    - 가격·판매 상태·재고는 이용 마트 기준으로 표시
    - 판매 단위·품절 여부 표시

### 관리자

- **관리자 감사 로그** (담당: 태헌 — 마트·상품·카테고리·재고 기록 연동, 공통 감사 기능: 채빈)
    - 관리자가 수행한 등록·수정·삭제·상태 변경과 개인정보가 보이는 조회를 ADMIN_AUDIT_LOG에 기록
    - 기록 항목은 관리자·작업 종류·대상 종류와 ID·관련 마트·변경 전후 값(details)·접속 IP·기록 시각이며, 목록 조회의 대상 ID와 details는 비워 둘 수 있음
    - 내부 DB 변경은 작업과 감사 기록을 같은 쓰기 가능한 트랜잭션으로 처리하고 기록 실패 시 작업도 롤백
    - 개인정보가 보이는 조회도 조회와 감사 기록을 같은 쓰기 가능한 트랜잭션으로 처리하며, 기록에 실패하면 조회 결과를 반환하지 않음
    - 외부 결제사 호출이 필요한 관리자 작업은 요청 접수 상태와 감사 로그를 먼저 함께 저장·커밋한 뒤 외부 호출을 수행하고 최종 결과는 별도 트랜잭션으로 반영
    - 각 도메인은 global의 공통 기록 인터페이스 AdminAuditRecorder를 호출하고 구현은 회원 도메인이 제공하며, 원래 작업을 조립하는 위치에서 중복 없이 기록
    - details에는 필요한 변경 전후 값만 기록하고 기존 이력 표와 연결하지 않으며, 개인정보·비밀번호·비밀번호 해시·토큰·빌링키·비밀키는 넣지 않음
    - 조회 응답 본문·이메일·이름 검색어와 거절 사유 등 자유 입력 원문은 감사 로그에 복사하지 않음
    - 실제 변경이나 새 실행이 없는 쓰기 재요청은 기록하지 않고 개인정보 조회는 요청마다 기록
    - 환불 재처리는 새 실행을 시작하면 기록하되 같은 멱등 키의 재전송과 구분하며, 최종 기록 시점과 전달 항목은 결제 담당과 확정
    - 시스템 결제 만료·자동 취소 등 자동 처리는 별도의 관리자 행위로 기록하지 않음
    - 접속 IP는 서버가 직접 확인한 주소를 기본으로 하며, 배포 후에는 신뢰하도록 설정한 프록시가 정리해 전달한 헤더만 사용
    - 감사 로그는 추가만 가능하며 관리자 수정·삭제 API를 두지 않고, 생성 시각부터 1년이 지난 기록은 내부 배치가 삭제
    - 기록 대상
        - 회원·멤버십: 멤버십 지급, 회원 목록·회원별 멤버십 이력 조회
        - 마트·상품: 마트 등록·수정·운영 상태 변경, 카테고리 등록·수정·삭제, 상품 등록·수정·삭제·가격·판매 상태·재료 연결 변경, 관리자 수동 재고 조정
        - 레시피: 레시피 등록·수정·상태 변경, 레시피 재료 변경, 재료 등록·수정, 관리자의 자동 장보기 지정·해제
        - 주문: 주문 수락·거절·배송 상태 변경
        - 결제: 관리자 환불 재처리, 관리자 결제·포인트 조회
        - AI: 관리자 AI 요청 이력 조회
    - 슈퍼 관리자만 기간·관리자·작업 종류·대상 종류로 목록을 검색하고 상세를 조회
    - 감사 로그 조회는 GET /api/admin/audit-logs 및 /api/admin/audit-logs/{id}로 제공. 기간은 한국 시간 from 포함·to 미포함이며 생성 시각·ID 내림차순으로 페이지 조회(기본 20개, 최대 100개)
    - 회원 목록 조회는 검색어·응답 본문 없이 매 요청 기록하고, 멤버십 지급은 새 이용권 ID와 유형·발급 경로·시작·종료 시각·자동갱신의 변경 전후 값만 기록
    - 만료 감사 로그는 매일 04:20 KST에 생성 시각 기준 1년이 지난 건을 최대 1,000건씩 별도 트랜잭션으로 조건부 삭제. 중복 실행에 안전하므로 별도 분산 락·추가 환경변수는 사용하지 않음
- **마트 관리** (담당: 태헌)
    - 지역(법정동)별 마트 1곳, 시연은 서로 떨어진 두 동네의 마트 2곳
    - 마트 등록 요청에 지역 ID를 직접 입력하고, 없는 지역 ID는 거절(지역은 초기 데이터로 고정, 지역 조회 API는 두지 않음)
    - 마트 위도·경도·서비스 반경 관리(서비스 반경은 구현 완료 후 도입, 지금은 판정에 쓰지 않음)
    - 운영 상태(운영·중지) 관리. 마트 관리자는 본인 마트의 운영 상태만 변경할 수 있고, 위도·경도·서비스 반경은 슈퍼 관리자만 수정
- **상품 관리** (담당: 태헌)
    - 판매 단위는 g·ml·개 정량
    - 상품에 브랜드 등록
    - 판매 중지
    - 주문 이력이 있어도 상품을 삭제할 수 있음(소프트 삭제). 지난 주문은 주문 당시 값(`ORDER_ITEM`)으로 유지되고, 진행 중인 주문은 그대로 이어지며, 삭제된 상품은 회원 조회에서 제외되고 담기·주문이 막힘
    - 마트 관리자는 자기 마트 상품을 등록·수정·삭제하고 가격·재고·판매 상태를 변경할 수 있으며, 결제·환불 처리는 슈퍼 관리자와 시스템만 함
    - 각 마트의 상품은 무조건 해당 마트에 등록되어 있어야 하고, 다른 마트로 변경 불가
    - 같은 마트에서 삭제되지 않은 상품은 이름과 브랜드가 모두 같으면(브랜드 없음끼리도 이름이 같으면) 중복 등록·수정 불가
    - 카테고리는 슈퍼 관리자만 등록·이름 수정·삭제(소프트 삭제)하고, 삭제되지 않은 상품이 연결된 카테고리는 삭제할 수 없음. 삭제된 카테고리와 같은 이름으로 등록하면 기존 카테고리를 복구
- **재료·상품 연결** (담당: 태헌)
    - 상품 등록·수정 시 해당하는 재료 지정(재료 하나에 여러 상품 가능, 재료가 아닌 상품은 미지정). 수정 시 재료 연결 해제 가능
    - 재료 단위와 상품 판매 단위의 호환 여부 검증
- **재고 관리** (담당: 태헌)
    - 마트별 상품 재고 조회·증가·감소
    - 마트별 상품 등록·수정
    - 조정 시 조정 전 수량·증감 수량·사유·처리 관리자 기록
    - 상품별 재고 조정 이력을 최신순으로 조회
