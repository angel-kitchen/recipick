## 1차

### 일반 회원

- **회원 탈퇴** (담당: 정윤 — 결제·환불·포인트·결제수단 연동, 탈퇴 기능: 채빈)
    - 로그인한 회원이 비밀번호를 다시 입력(재인증)해 탈퇴
    - 결제 대기·취소 처리 중인 주문, 정상 진행 중인 배송 미완료 주문, 미해결 결제·환불, 활성 멤버십(해지 예약 포함)이 있으면 탈퇴할 수 없으며 먼저 처리하도록 안내
    - 탈퇴 정산 확인은 3차까지 포함해 상품 결제(결과 불명·SYSTEM 환불·수동 확인), 멤버십 결제(구독·갱신·재시도·결과 불명·이용료 환불), 포인트(잔액 사전 안내·미정산 내역·소멸 처리), 자동결제(탈퇴 후 신규 청구 방지·결제수단 처리)를 확인 범위로 함
    - 각 영역의 실제 상태 판정과 정리 방식은 담당자와 합의해 연결하며, 일부 영역만 연결되거나 확인에 실패하면 탈퇴를 허용하지 않음. 장바구니·찜의 정리 계약도 별도로 확정
    - 외부 결제수단 정리가 필요하면 회원 잠금 트랜잭션 밖에서 별도 절차로 처리하고, 이미 시작된 거래의 후속 처리에는 탈퇴 검사를 추가하지 않음
    - 취소·환불이 완료되어 종료된 주문과 배송 완료 주문은 탈퇴를 제한하지 않음. 다만 관련 미해결 결제·환불이 남아 있으면 탈퇴 불가
    - 탈퇴와 탈퇴 제한 상태를 새로 만드는 작업은 같은 회원 행을 잠가 경합을 제어하며, 탈퇴는 잠금 후 탈퇴 여부·진행 중 주문·미해결 결제·환불·활성 멤버십을 확인
    - 탈퇴하면 로그인·토큰 재발급을 차단하고 모든 기기의 리프레시 토큰을 폐기하며, 기존 액세스 토큰으로 요청해도 회원 인증 시 탈퇴 여부를 확인해 접근을 거절
    - 회원 정보의 이메일·이름·휴대전화는 고유한 대체값으로 바꾸고, 현재 배송지 선택과 이용 마트를 해제한 뒤 배송지를 삭제
    - 주문에 기록된 수령인·연락처·배송 주소와 결제·멤버십 기록은 회원 정보 정리와 별개로 보관하며, 항목별 보존 근거·기간과 만료 후 파기 방식은 별도로 확정
    - 장바구니·찜·포인트·결제수단 등 다른 도메인 데이터의 정리 범위는 해당 담당과 정하며, 탈퇴로 소멸되는 포인트 잔액은 탈퇴 전에 안내
    - 멤버십 이용 이력(관리자 지급 포함)이 있는 회원이 탈퇴하면 휴대전화의 키 해시(HMAC-SHA-256)를 TRIAL_BLOCK에 탈퇴 시각부터 1년간 보관
    - 같은 번호로 재가입하면 가입·유료 구독은 가능하지만 차단 기간 중에는 무료체험을 받을 수 없으며, 만료된 차단 기록은 체험 자격을 제한하지 않음
    - 차단 기간 중 이용 이력 없이 재가입·재탈퇴하면 기존 만료일을 유지하고, 새 계정에 멤버십 이용 이력이 있으면 새 탈퇴 시각부터 1년으로 연장
    - 해시 보관 항목·사유·기간은 탈퇴 화면과 개인정보처리방침에 표시하고, 만료된 기록은 내부 배치가 삭제
    - 회원 쪽 탈퇴 기반을 먼저 준비하되 주문·결제·포인트 등 필요한 연동과 경합 검증이 끝나기 전에는 탈퇴 기능을 제공하지 않음
- **상품 결제** (담당: 정윤)
    - PortOne 카드 결제
    - 주문 생성 트랜잭션에서 `ORDER`와 `PAYMENT(IN_PROGRESS)`를 함께 생성
    - 결제 유효시간은 주문·결제 생성 시점부터 **5분**
    - 서버가 PortOne 결제 상태·주문 식별자·결제 금액을 다시 조회해 검증한 뒤에만 결제 확정
    - PG 실제 결제 완료시각(`paidAt`)이 결제 만료시각(`expiresAt`) 이내인지 검증
    - 결제 성공 시 `PAYMENT = PAID` , `ORDER = PAID` , 마트 처리 상태를 `RECEIVED(접수중)` 로 같은 트랜잭션에서 반영
    - 웹훅도 동일한 검증·상태 전이 로직으로 처리
    - 결제 확정 API·웹훅·만료 큐가 동시에 들어와도 결제 성공은 한 번만 반영
- **결제 실패·만료** (담당: 정윤)
    - PG가 결제 실패를 명확히 확정하면 `PAYMENT = FAILED(PG_FAILED)` 처리
    - 5분 내 결제가 완료되지 않으면 지연 큐에서 `PAYMENT = FAILED(EXPIRED)` 처리
    - 실패·만료 시 주문을 `CANCELED`로 종료하고 주문 생성 시 차감한 재고 복구
    - 기존 실패 주문·결제를 다시 사용하지 않으며, 다시 결제하려면 **새 주문·새 결제 생성**
    - 기존 결제대기 주문이 있으면 새 주문 생성 불가
    - PG 응답이 불명확하면 실패로 단정하지 않고 기존 결제 상태를 조회해 결과 확인
    - 내부적으로 이미 종료된 결제에서 뒤늦은 PG 성공이 확인되면 주문을 되살리지 않고 시스템 자동 취소
- **결제 전 취소** (담당: 정윤)
    - `PAYMENT = IN_PROGRESS` 상태에서 회원이 결제를 취소할 수 있음
    - 결제 전·후 취소는 동일한 취소 API를 사용하며 `Idempotency-Key` 를 필수로 전달
    - 결제 전 취소는 PG 취소 호출과 `REFUND` 생성을 하지 않음
    - `PAYMENT = FAILED(CANCELED_BEFORE_PAY)` 처리
    - 주문 `CANCELED`, `pending_member_id` 해제
    - 주문 생성 시 차감한 재고 복구
    - 같은 종료 처리가 중복 실행되지 않도록 결제·주문 상태를 기준으로 멱등 처리
- **결제 후 취소** (담당: 정윤)
    - 결제 완료 후 마트 상태가 `RECEIVED(접수중)` 일 때만 회원 직접 전체 취소 가능
    - `PREPARING(배송준비중)` 부터는 회원 직접 취소·환불 불가
    - 부분 취소·부분 환불 없음
    - 취소 시작 시 `PAYMENT/ORDER = CANCEL_REQUESTED`, `REFUND = REQUESTED`를 먼저 저장
    - PortOne 취소 호출은 DB 트랜잭션 밖에서 수행
    - PG 취소 성공 시 `PAYMENT = CANCELED`, `ORDER = REFUNDED`, `REFUND = COMPLETED` 처리 및 재고 복구
    - PG 취소 결과가 불명확하면 `CANCEL_REQUESTED / REQUESTED` 상태를 유지하고 웹훅·재조회로 결과 확인
    - 회원 취소가 명확히 실패하면 결제·주문을 `PAID`, 마트 상태를 `RECEIVED`로 복구
- **환불 처리** (담당: 정윤)
    - PortOne 취소 성공을 확인한 뒤에만 환불 완료 처리
    - 환불 요청 주체 `MEMBER / ADMIN / SYSTEM / EXTERNAL` 기록
    - `Idempotency-Key`로 같은 PG 취소가 중복 실행되지 않도록 처리
    - 동일 환불이 진행 중이면 새 환불 요청을 중복 생성하지 않음
    - 만료·금액 불일치 후 PG 결제 성공이 확인되면 `SYSTEM` 환불 실행
    - 만료 시 이미 주문 종료·재고 복구가 완료됐으므로 늦은 승인 자동환불에서는 주문·재고를 다시 변경하지 않음
- **결제 내역 조회** (담당: 정윤)
    - 본인 주문별 결제 금액·결제 방식·결제 일시·결제 상태·실패 사유·취소 여부 조회
    - 결제 도메인은 주문 엔티티를 직접 조회하지 않고 주문 서비스의 소유 확인·조회 계약을 사용
    - 실패·취소된 결제도 이력으로 유지
    - 취소가 발생한 결제는 완료 환불 금액과 최근 환불 상태 표시

### 관리자

- **관리자 감사 로그** (담당: 정윤 — 결제·포인트 조회 및 환불 재처리 기록 연동, 공통 감사 기능: 채빈)
    - 관리자가 수행한 등록·수정·삭제·상태 변경과 개인정보가 보이는 조회를 ADMIN_AUDIT_LOG에 기록
    - 기록 항목은 관리자·작업 종류·대상 종류와 ID·관련 마트·변경 전후 값(details)·접속 IP·기록 시각이며, 목록 조회의 대상 ID와 details는 비워 둘 수 있음
    - 내부 DB 변경은 작업과 감사 기록을 같은 쓰기 가능한 트랜잭션으로 처리하고 기록 실패 시 작업도 롤백
    - 개인정보가 보이는 조회도 조회와 감사 기록을 같은 쓰기 가능한 트랜잭션으로 처리하며, 기록에 실패하면 조회 결과를 반환하지 않음
    - 외부 결제사 호출이 필요한 관리자 작업은 요청 접수 상태와 감사 로그를 먼저 함께 저장·커밋한 뒤 외부 호출을 수행하고 최종 결과는 별도 트랜잭션으로 반영
    - 각 도메인은 global의 공통 기록 인터페이스 AdminAuditRecorder를 호출하고 구현은 회원 도메인이 제공하며, 원래 작업을 조립하는 위치에서 중복 없이 기록
    - details에는 필요한 변경 전후 값만 기록하고 기존 이력 표와 연결하지 않으며, 개인정보·비밀번호·비밀번호 해시·토큰·빌링키·비밀키는 넣지 않음
    - 조회 응답 본문·이메일·이름 검색어와 거절 사유 등 자유 입력 원문은 감사 로그에 복사하지 않음
    - 실제 변경이나 새 실행이 없는 쓰기 재요청은 기록하지 않고 개인정보 조회는 요청마다 기록
    - 환불 재처리는 새 실행을 시작하면 기록하되 같은 멱등 키의 재전송과 구분하며, 최종 기록 시점과 전달 항목은 결제 담당과 확정
    - 시스템 결제 만료·자동 취소 등 자동 처리는 별도의 관리자 행위로 기록하지 않음
    - 접속 IP는 서버가 직접 확인한 주소를 기본으로 하며, 배포 후에는 신뢰하도록 설정한 프록시가 정리해 전달한 헤더만 사용
    - 감사 로그는 추가만 가능하며 관리자 수정·삭제 API를 두지 않고, 생성 시각부터 1년이 지난 기록은 내부 배치가 삭제
    - 기록 대상
        - 회원·멤버십: 멤버십 지급, 회원 목록·회원별 멤버십 이력 조회
        - 마트·상품: 마트 등록·수정·운영 상태 변경, 카테고리 등록·수정·삭제, 상품 등록·수정·삭제·가격·판매 상태·재료 연결 변경, 관리자 수동 재고 조정
        - 레시피: 레시피 등록·수정·상태 변경, 레시피 재료 변경, 재료 등록·수정, 관리자의 자동 장보기 지정·해제
        - 주문: 주문 수락·거절·배송 상태 변경
        - 결제: 관리자 환불 재처리, 관리자 결제·포인트 조회
    - 슈퍼 관리자만 기간·관리자·작업 종류·대상 종류로 목록을 검색하고 상세를 조회
- **결제 조회** (담당: 정윤)
    - `SUPER_ADMIN` 전용
    - 회원·기간·결제 상태 조건으로 결제 목록 조회
    - 주문별 결제 금액·결제 상태·PortOne 결제 번호 확인
    - 결제 상세에서 모든 취소·환불 실행 이력 확인
    - 실패한 환불 실행 기록도 삭제하지 않고 운영 이력으로 유지

## 2차

### 일반 회원

- **포인트 사용** (담당: 정윤)
    - 1포인트 = 1원
    - 1포인트부터 상품금액 전액까지 사용, 배송비에는 사용 불가
    - 만료일이 빠른 적립부터 사용
    - 한 주문에서 여러 적립 건의 포인트를 나누어 사용 가능
    - 주문 생성 시 `POINT_USAGE = RESERVED`
    - 예약 시 `MEMBER_POINT.balance`와 해당 `POINT_EARNING.remaining_amount` 차감
    - 결제 성공 시 `CONFIRMED`
    - 결제 실패·만료·취소 시 `RESTORED`
    - 주문 생성 당시 유효했던 예약 포인트는 5분 결제 대기 중 만료일이 지나도 해당 주문에서는 인정
    - 외부 결제금액이 0원이면 `PAYMENT`는 `payment_method = POINTS_ONLY`, `amount = 0`으로 생성하고 PG는 호출하지 않는다.
- **포인트 적립** (담당: 정윤)
    - 일반·체험 회원 적립률 0.5%
    - 적립액 = `(상품금액 − 사용 포인트) × 0.5%`
    - 배송비 제외, 소수점 이하 버림
    - 주문 생성 시 `POINT_EARNING = PENDING` 으로 적립 예정 건을 생성
    - **배송완료 시** `PENDING -> COMPLETED`로 적립 확정
    - 적립 확정 시 `MEMBER_POINT.balance` 증가
    - 주문당 적립 건 1개
    - 유효기간은 적립 확정일로부터 1년
    - `expires_on` 당일까지 사용 가능
- **취소 시 포인트 복원** (담당: 정윤)
    - 주문에서 사용한 포인트는 사용 당시 차감했던 원래 `POINT_EARNING` 적립 건으로 복원
    - 원래 `expires_on`은 연장하지 않음
    - 복원 시 이미 만료일이 지났다면 `RESTORED` 이력을 남긴 뒤 즉시 `EXPIRED` 처리
    - 이미 만료된 포인트는 `MEMBER_POINT.balance` 에 다시 추가하지 않음
    - 배송완료 전 주문이 종료되면 적립 예정 `POINT_EARNING` 은 `CANCELED`
    - 배송완료가 포인트 적립 확정이자 최종 거래 완료 시점이므로 **적립 완료 후 환불에 따른 포인트 회수(clawback)는 없음**
    - 포인트 전액결제 주문 취소 시 PG 호출 없이 내부적으로 사용 포인트 복원
- **포인트 조회** (담당: 정윤)
    - 회원별 현재 사용 가능 총 포인트 조회
    - 가장 가까운 만료 포인트와 만료일 조회
    - 주문별 적립 예정·적립 완료·사용 예약·사용 확정·복원·만료 이력 조회
    - 적립 건별 최초 적립량·남은 포인트·만료일 조회
    - 포인트 보유 이력이 없는 회원은 404가 아니라 잔액 0·빈 목록 반환

### 관리자

- **마트 주문 거절·자동 환불** (담당: 준희·정윤)
    - 마트 관리자는 본인 마트의 주문이 `PAID` 이고 마트 처리 상태가 `RECEIVED` 일 때만 주문을 거절할 수 있습니다.
    - 거절 요청 시 결제 Facade에서 `PAYMENT = CANCEL_REQUESTED`, `ORDER = CANCEL_REQUESTED`, 마트 처리 상태를 `REJECTED`, `REFUND = REQUESTED`로 먼저 저장합니다.
    - 거절 접수 시점에는 재고와 사용 포인트를 복구하지 않습니다.
    - PortOne 취소는 DB 트랜잭션 밖에서 전액 취소로 실행합니다.
    - PG 취소 성공 시 `PAYMENT = CANCELED`, `ORDER = REFUNDED`, `REFUND = COMPLETED`로 처리하고 최초 차감 재고를 한 번 복구합니다.
    - 사용 포인트가 있는 경우 원래 사용했던 적립 건으로 복원합니다.
    - PG 취소 결과가 불명확하면 `CANCEL_REQUESTED / REQUESTED / REJECTED` 상태를 유지하고 웹훅·재조회로 결과를 확인합니다.
    - PG 취소가 명확히 실패하면 `PAYMENT = PAID`로 복귀하지만 `ORDER = CANCEL_REQUESTED`, 마트 처리 상태 `REJECTED`는 유지하고 관리자 재처리 대상으로 관리합니다.
    - 관리자 재처리 시 새 `Idempotency-Key`와 새 환불 시도를 사용하며, 최종 성공 시 재고·포인트 복원은 한 번만 반영합니다.
- **포인트 조회** (담당: 정윤)
    - `SUPER_ADMIN` 전용
    - 회원별 현재 포인트 잔액 조회
    - 가장 가까운 만료 예정 포인트 확인
    - 회원별 적립·사용·복원·만료 감사 이력 조회
    - 적립 건 ID와 주문 ID를 함께 제공해 적립 lot 단위로 추적

## 3차

### 유료 회원

- **즉시 해지** (담당: 채빈, 환불 처리: 정윤)
    - 유료 멤버십 회원은 이용기간 중 즉시 해지 및 환불을 요청할 수 있습니다.
    - 즉시 해지 요청 API는 멤버십 도메인이 소유합니다.
    - 요청 시 `Idempotency-Key`를 필수로 받고 결제 도메인의 이용료 환불 서비스를 호출합니다.
    - 환불 처리 중에는 멤버십을 `ACTIVE`로 유지합니다.
    - 환불이 `COMPLETED`된 경우에만 멤버십을 즉시 종료합니다.
    - 환불이 명확히 실패하면 멤버십을 `ACTIVE`로 유지합니다.
    - 환불 결과가 불명확하면 `REQUESTED` 상태와 멤버십 `ACTIVE`를 유지하고 웹훅·재조회로 결과를 확인합니다.
    - 결과 불명 건이 나중에 환불 성공으로 확인되면 `즉시 해지 환불 완료 반영`을 통해 멤버십을 종료합니다.
    - 같은 `Idempotency-Key`로 다시 요청하면 새 환불을 만들지 않고 기존 결과를 반환합니다.
    - 같은 이용권에 결과 확인 중인 `REQUESTED` 환불이 있으면 다른 키의 새 요청은 거절합니다.
    - 명확한 실패가 `FAILED`로 확정된 뒤에는 새 `Idempotency-Key`로 다시 요청할 수 있습니다.
- **자동 결제 동의** (담당: 정윤 안내, 채빈 저장)
    - 체험·유료 구독 시작 전 결제 금액·첫 결제일·월 갱신 주기·자동갱신 해지·즉시 해지 방법 안내
    - 동의 금액·동의 문구 버전·동의 일시를 멤버십에 저장
    - 자동 청구 시 멤버십 도메인에 자동청구 대상·동의 여부 확인
- **카드 등록** (담당: 정윤)
    - 카드번호·CVC는 저장하지 않고 PortOne 빌링키만 관리
    - 회원당 `ACTIVE` BillingKey 최대 1개
    - 새 카드 등록 시 기존 ACTIVE 키는 `REPLACED`, 새 키는 `ACTIVE`
    - 동일 ACTIVE BillingKey 재등록은 새 행을 만들지 않고 기존 결과 반환
    - 자동결제 customer 개인정보(name/email/phone)는 BillingKey에 중복 저장하지 않음
    - 실제 자동결제 시 MemberService의 결제용 회원정보 조회를 통해 원문을 받아 Customer DTO 구성
- **멤버십 결제** (담당: 정윤)
    - 월 이용료 3,900원
    - 체험 종료 또는 일반회원의 유료 구독 시작 시 첫 자동 결제
    - 이후 첫 유료 결제일을 기준으로 매월 같은 날짜에 자동청구
    - 해당 날짜가 없는 달은 말일 청구
    - 청구 대상은 멤버십 서비스에서 조회
    - 동일 이용권의 같은 이용기간 회차 결제는 한 번만 생성
    - `UNIQUE(membership_id, period_start_date)`로 회차 중복 생성 방지
    - PortOne 자동결제 성공 후 멤버십 도메인에 결과 반영
- **첫 유료 결제 실패** (담당: 정윤)
    - 체험 종료 후 첫 결제가 명확히 실패하면 `FAILED` 결과 전달
    - 멤버십 도메인은 유료 전환하지 않고 일반 회원으로 전환
    - PG 결과가 불명확하면 즉시 실패로 단정하지 않고 `UNKNOWN` 상태로 조회해 결과 확정
- **갱신 결제 실패** (담당: 정윤)
    - 기존 유료 멤버십 갱신 실패 시 3일 유예
    - 갱신일에 1회, 이후 하루 1회씩 2회 추가해 총 3회 시도
    - 재시도 대기 상태는 `RETRY_WAITING`
    - 결과 불명(`UNKNOWN`)은 새 결제 시도보다 기존 PG 결과 조회를 우선
    - 최종 실패 시 멤버십 도메인에 최종 실패 결과 전달
- **갱신 시 카드 없음** (담당: 정윤)
    - 갱신일에 활성 BillingKey가 없으면 `PAYMENT_METHOD_REQUIRED` 3일간 카드 등록 대기
    - 유예기간 내 카드 등록 시 한 번 청구
    - 기간 종료까지 카드가 없으면 최종 실패 결과 전달
- **이용료 환불** (담당: 정윤)
    - 유료 멤버십 즉시 해지 요청의 내부 처리로 실행
    - 회원이 멤버십 결제 환불 API를 직접 호출하지 않음
    - 멤버십은 환불 결과가 확정될 때까지 `ACTIVE` 유지
    - 환불액 = `max(0, 결제금액 - 이용일수 요금 - 위약금)`
    - 이용일수 요금 = `floor(결제금액 x 이용일수 / 해당 결제기간 실제 일수)`
    - 위약금 = 결제금액의 20%
    - 이용일수는 이용 시작일과 환불 요청일을 모두 포함
    - 이용일수·이용일수 요금·위약금·환불금액을 `MEMBERSHIP_REFUND`에 저장
    - 환불 요청 시 `MEMBERSHIP_REFUND = REQUESTED`를 먼저 저장·커밋한 뒤 PortOne 환불 호출
    - 환불 성공 시 `COMPLETED` 처리 후 멤버십 종료
    - 명확한 실패 시 `FAILED`, 멤버십 `ACTIVE` 유지, 새 요청 가능
    - 결과 불명 시 `REQUESTED` 유지, 멤버십 `ACTIVE` 유지 후 웹훅·재조회로 확인
    - 결과 불명 건이 나중에 성공으로 확인되면 `COMPLETED` 처리 후 멤버십의 즉시 해지 환불 완료 반영 호출
    - 환불액이 0원이면 PG 호출 없이 `COMPLETED` 처리 후 멤버십 종료
    - 동일 요청은 `Idempotency-Key`로 중복 환불 방지
- **적립률 차등** (담당: 정윤)
    - 유료 멤버십 1%, 체험 0.5%(일반 회원 0.5%)
    - 적립률은 **주문 생성 시점의 회원 상태**로 결정해 주문에 스냅샷
    - 실제 포인트 지급은 배송완료 시점
    - 이후 회원 멤버십 상태가 바뀌어도 해당 주문의 적립률은 변경하지 않음

### 관리자

- **멤버십 결제 조회** (담당: 정윤)
    - `SUPER_ADMIN` 전용
    - 첫 결제·월 정기결제·실패·재시도·결제수단 필요·결과 불명 상태 조회
    - 청구일·이용기간·시도 횟수·다음 재시도 시각·실패 사유 확인

    - 환불 금액·이용일수·이용요금·위약금·처리상태·실패사유 확인
