## 1차

### 일반 회원

- **회원가입·로그인** (담당: 채빈)
    - 이메일 기반 일반 회원 가입·로그인
    - 가입 시 이름·휴대전화 입력, 이메일·휴대전화 중복 불가
    - 서비스 이용약관·개인정보 수집 동의 필수, 동의 일시 저장
    - 로그인 3회 연속 실패 시 10분 잠금
    - 액세스 토큰 30분, 리프레시 토큰 14일(HttpOnly 쿠키, Redis 저장), 로그아웃 시 폐기
    - 관리자는 별도 로그인
    - 본인의 장바구니·주문·결제·포인트 정보만 접근
- **비밀번호 변경** (담당: 채빈)
    - 로그인한 회원이 현재 비밀번호를 확인한 뒤 새 비밀번호로 변경
    - 새 비밀번호는 가입 때와 같은 규칙(8~20자, 영문·숫자·특수문자 포함, 공백 불가)으로 검증
    - 현재 비밀번호가 맞지 않으면 변경하지 않음
    - 변경하면 모든 기기의 리프레시 토큰을 폐기해 토큰 재발급을 차단하고, 이미 발급된 액세스 토큰은 만료(30분)까지 사용할 수 있음
    - 비밀번호 변경은 회원 행을 잠근 뒤 처리하고, 비밀번호 해시와 리프레시 세션 버전을 같은 DB 트랜잭션에서 변경해 동시 로그인·재발급의 이전 버전 토큰도 무효화
    - 변경 전 Redis 세션 키 목록을 확보하고 DB 커밋 뒤 해당 키만 정리하며, 정리가 실패하거나 늦게 저장된 이전 세션이 남아도 버전 검사로 재발급을 거절. 남은 키는 TTL로 만료
    - 비밀번호 오류·입력 검증 실패 시 비밀번호와 세션 버전을 변경하거나 Redis 세션을 삭제하지 않음
- **회원 탈퇴** (담당: 채빈 — 탈퇴 계정 인증·토큰 재발급 차단)
    - 로그인한 회원이 비밀번호를 다시 입력(재인증)해 탈퇴
    - 결제 대기·취소 처리 중인 주문, 정상 진행 중인 배송 미완료 주문, 미해결 결제·환불, 활성 멤버십(해지 예약 포함)·결제 대기 유료 이용권·전환 대기 체험 이용권이 있으면 탈퇴할 수 없으며 먼저 처리하도록 안내
    - 탈퇴 정산 확인은 3차까지 포함해 상품 결제(결과 불명·SYSTEM 환불·수동 확인), 멤버십 결제(구독·갱신·재시도·결과 불명·이용료 환불), 포인트(잔액 사전 안내·미정산 내역·소멸 처리), 자동결제(탈퇴 후 신규 청구 방지·결제수단 처리)를 확인 범위로 함
    - 각 영역의 실제 상태 판정과 정리 방식은 담당자와 합의해 연결하며, 일부 영역만 연결되거나 확인에 실패하면 탈퇴를 허용하지 않음. 장바구니·찜의 정리 계약도 별도로 확정
    - 외부 결제수단 정리가 필요하면 회원 잠금 트랜잭션 밖에서 별도 절차로 처리하고, 이미 시작된 거래의 후속 처리에는 탈퇴 검사를 추가하지 않음
    - 취소·환불이 완료되어 종료된 주문과 배송 완료 주문은 탈퇴를 제한하지 않음. 다만 관련 미해결 결제·환불이 남아 있으면 탈퇴 불가
    - 탈퇴와 탈퇴 제한 상태를 새로 만드는 작업은 같은 회원 행을 잠가 경합을 제어하며, 탈퇴는 잠금 후 탈퇴 여부·진행 중 주문·미해결 결제·환불·활성 멤버십을 확인
    - 탈퇴하면 로그인·토큰 재발급을 차단하고 모든 기기의 리프레시 토큰을 폐기하며, 기존 액세스 토큰으로 요청해도 회원 인증 시 탈퇴 여부를 확인해 접근을 거절
    - 회원 정보의 이메일·이름·휴대전화는 고유한 대체값으로 바꾸고, 현재 배송지 선택과 이용 마트를 해제한 뒤 배송지를 삭제
    - 주문에 기록된 수령인·연락처·배송 주소와 결제·멤버십 기록은 회원 정보 정리와 별개로 보관하며, 항목별 보존 근거·기간과 만료 후 파기 방식은 별도로 확정
    - 장바구니·찜·포인트·결제수단 등 다른 도메인 데이터의 정리 범위는 해당 담당과 정하며, 탈퇴로 소멸되는 포인트 잔액은 탈퇴 전에 안내
    - 장바구니는 탈퇴 차단 조건이 아니며, 정산 확인을 모두 통과한 뒤 같은 탈퇴 트랜잭션에서 회원의 장바구니 항목을 모두 삭제하고 담기 이력은 유지. 탈퇴가 거절되면 삭제도 함께 롤백
    - 탈퇴 전 실제 사용 가능 포인트를 안내하고, `POST /api/members/me/withdraw`에 `password`와 사용자가 확인한 `acknowledgedPointBalance`(필수, 0 이상의 Long, 잔액이 없으면 0)를 전달
    - 회원 쪽은 확인 잔액을 기본값으로 대체하지 않고 `WithdrawalSettlementChecker.requireSettled(memberId, acknowledgedPointBalance)`에 그대로 전달. POINTS 구현이 회원 잠금 이후 포인트를 잠그고 지연 만료·미정산 확인·실제 잔액 비교·소멸을 수행하며 다른 Scope는 확인 잔액을 사용하지 않아도 됨
    - 잔액만 있으면 탈퇴를 막지 않고 안내한 잔액과 실제 잔액이 같을 때 소멸 처리. 다르면 POINT-002(409)로 거절해 최신 잔액을 재확인하며 예외 시 지연 만료를 포함한 해당 트랜잭션 변경을 모두 롤백. 재안내용 잔액 조회도 유효기간을 반영
    - 포인트의 PENDING 적립·RESERVED 사용은 POINT-003(409)으로 탈퇴 차단. 포인트 잔액과 적립 원장의 합계가 맞지 않는 상태는 회원이 해결할 수 없는 문제라 409가 아닌 내부 오류(COMMON-500)로 차단하고 운영이 확인. CONFIRMED 사용 자체와 완료 이력만으로 차단하지 않으며 잔액이 0이어도 미정산 검사를 수행
    - 포인트 탈퇴 소멸은 자연 만료와 구분해 FORFEITED·WITHDRAWAL_FORFEITED로 기록하고 소멸 금액이 없으면 소멸 이력을 생성하지 않음(포인트 구현: 정윤)
    - 실제로 활성화된 멤버십 이용 이력(관리자 지급 포함, activated_at이 있는 이력)이 있는 회원이 탈퇴하면 휴대전화의 키 해시(HMAC-SHA-256)를 TRIAL_BLOCK에 탈퇴 시각부터 1년간 보관
    - 같은 번호로 재가입하면 가입·유료 구독은 가능하지만 차단 기간 중에는 무료체험을 받을 수 없으며, 만료된 차단 기록은 체험 자격을 제한하지 않음
    - 차단 기간 중 이용 이력 없이 재가입·재탈퇴하면 기존 만료일을 유지하고, 새 계정에 멤버십 이용 이력이 있으면 새 탈퇴 시각부터 1년으로 연장
    - 해시 보관 항목·사유·기간은 탈퇴 화면과 개인정보처리방침에 표시하고, 만료된 기록은 내부 배치가 삭제
    - 회원 쪽 탈퇴 기반을 먼저 준비하되 주문·결제·포인트 등 필요한 연동과 경합 검증이 끝나기 전에는 탈퇴 기능을 제공하지 않음

### 관리자

- **관리자 로그인** (담당: 채빈)
    - 관리자 전용 로그인
    - 관리자 계정은 초기 데이터로만 생성(가입 불가)
    - 관리자 역할과 소속 마트 구분
    - 비활성 계정은 로그인 거부
    - 관리자 API는 관리자 토큰만 허용
    - 로그인 3회 연속 실패 시 10분 잠금(회원과 동일)
